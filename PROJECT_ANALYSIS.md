# PROJECT_ANALYSIS.md

# Архитектура проекта «Мафиози»

Документ создан как обзор текущей кодовой базы без изменения игрового кода.
Последний просмотренный коммит: `360985c4f292ae10ab73c580bd117898d01dea65` от 2026-07-07, изменение гонки в `world.html`.

## 1. Общая картина

«Мафиози» — Telegram-бот с HTML5 WebApp-играми. Главный текущий фокус проекта — `world.html`, открытый изометрический онлайн-мир. Игрок заходит из Telegram в `hub.html`, оттуда открывает `world.html`, а сам мир подключается к Python-серверу через WebSocket `/world/sim`.

Высокоуровневая схема:

```text
Telegram user
  -> mafiozi_bot.py /start
  -> WebApp кнопка hub.html на GitHub Pages
  -> hub.html подтягивает актуальный API из coop_api.json
  -> world.html?api=...&uid=...&look=...
  -> WebSocket wss://<cloudflared>/world/sim
  -> WorldSim в mafiozi_bot.py
  -> SQLite mafiozi.db
```

Клиентские файлы лежат как статические HTML на GitHub Pages (`slavaprivet.github.io/mafiozi-battle`). Серверная часть запускается локально или на хостинге, наружу отдаётся через cloudflared-туннель. Актуальный адрес туннеля публикуется в `coop_api.json`.

## 2. Ключевые файлы

### `world.html`

Главный файл открытого мира. Это монолитный HTML с CSS, UI, Canvas-рендером, управлением, локальными NPC, машинами, банками, районами, событиями и WebSocket-клиентом.

Основные подсистемы:

- изометрическая карта `MAP`, `MAP_ROWS`, `MAP_COLS`, `BLOCK=10`;
- южная зона: Логово, пляж, пирс, корабль Майкла, гоночный трек;
- локальное движение игрока и машин;
- локальные NPC: прохожие, городские патрульные, питомцы, декор;
- серверные сущности из snapshot: другие игроки, world cops, aggro bots, gang nests, beachgoers, Michael guards, quest cars, territories, districts;
- банк-интерьер и ограбления банков;
- система оружия, пуль, отдачи, muzzle/impact/smoke эффектов;
- UI: HUD, weapon bar, чаты над головой, баннеры, модалки, режим PvP/PvE;
- WS-клиент: `wsUrl()`, `wsConnect()`, `sendInput()`, `sendShoot()`, обработка `snap` и `event`.

Важно: `world.html` не просто отображает серверное состояние. Он держит много клиентской авторитетной логики: транспорт, интерьер банка, часть урона, NPC-проходки, визуальные события, декор и взаимодействия. Поэтому любые изменения надо делать рядом с существующей подсистемой, а не создавать параллельную.

### `mafiozi_bot.py`

Большой Python-монолит. Совмещает:

- Telegram-бота на `python-telegram-bot`;
- SQLite-модель игрока и экономики;
- aiohttp HTTP API для WebApp;
- WebSocket-серверы для co-op и открытого мира;
- серверную симуляцию `WorldSim`;
- Telegram callback-меню, бои, работы, банды, рейды, магазин, имущество.

Для открытого мира главное:

- `WorldSim` — глобальная серверная комната;
- `_world_get()` — лениво создаёт единственный `WorldSim`;
- `_world_run_loop()` — тик 15 Гц, чистка AFK, AI, события, снапшоты;
- `h_world_ws()` — WebSocket `/world/sim?uid=...`;
- `snapshot_for()` — формирует состояние для конкретного игрока;
- обработчики WS-сообщений: `input`, `chat`, `player_shoot`, `cop_shoot`, `capture_try`, `district_capture_try`, `gta_*`, `bank_rob_*`, `brigadir_*`, `world_heal`, `race_lap` и другие.

### `hub.html`

Хаб игрока. Получает все основные параметры из URL, рисует профиль/меню и открывает `world.html`. Для мира важна функция `openWorld()`: она подтягивает свежий API из `coop_api.json`, прокидывает `uid`, `name`, внешность, флаг/название банды, `mark_lvl`, `hub`-URL и cache-buster.

### `battle.html`, `demo_isometric.html`, `creator.html`

`battle.html` — отдельная PvP/боёвка, сейчас менее центральна для open world.

`demo_isometric.html` — эталон физики пуль и HP-бара. По проектным правилам его нельзя менять, но надо сверяться с ним при правках оружия, пуль, HP и боевых эффектов.

`creator.html` — редактор внешности. Его рендер частично скопирован в `hub.html`.

### `start_with_tunnel.py`

Запускает `cloudflared.exe tunnel --url http://localhost:8080`, ловит публичный `trycloudflare.com` URL, пишет его в `COOP_API_BASE`, запускает `mafiozi_bot.py`, публикует `coop_api.json` в GitHub Pages через GitHub API.

### `github_upload_world.py`

Публикует `world.html` в репозиторий GitHub Pages через GitHub API. Перед заливкой запускает `check_world.py`, после PUT сверяет GitHub API blob SHA. Это проектный путь публикации `world.html`.

### `check_world.py` и `check_bot.py`

`check_world.py` вытаскивает inline `<script>` из HTML и гоняет `node --check`.

`check_bot.py` проверяет, что `mafiozi_bot.py` парсится через `ast.parse`, и что файл не обрезан.

## 3. Карта и координаты

В открытом мире используется tile-based изометрия:

- `r` — строка/вертикальная координата мира;
- `c` — колонка/горизонтальная координата мира;
- сервер в WS часто хранит `x=c`, `y=r`;
- клиентские функции `w2s(r,c)` и `s2w(x,y)` переводят мир в экран и обратно;
- `BLOCK=10`, квартал 10x10: дорога `mod <= 3`, бордюр `mod == 4 || 9`, внутренний блок здания `mod 5..8`.

Карта сейчас фактически `80x200`, хотя старые документы местами говорят `80x80`. Верхние `r=0..99` — город, `r=100..149` — Логово/буфер, `r=150..199` — пляж, вода, пирс, корабль и гоночный трек. Серверные константы `WORLD_MAP_COLS`, `WORLD_MAP_ROWS`, южная зона и трек должны совпадать с `world.html`.

Самая опасная область — синхронизация карты между клиентом и сервером:

- `_world_is_wall()` в сервере вручную повторяет правила `buildMap()`;
- южная зона и гоночный трек продублированы в Python и JS;
- при изменении геометрии надо менять обе стороны.

## 4. WebSocket-протокол открытого мира

Клиент подключается к:

```text
wss://<api>/world/sim?uid=<telegram_id>&mode=pvp|pve&gang_flag=...&gang_name=...
```

Сервер отправляет:

- `hello` — параметры карты, tick rate, время сервера;
- `snap` — основное состояние мира;
- `event` — точечные события;
- отдельные ответы вроде `race_top`.

Клиент отправляет:

- `input` — позиция игрока, угол, walking, оружие, мешок, иногда gang snapshot;
- `chat` — короткий текст над головой;
- боевые события: `player_shoot`, `cop_shoot`, `aggro_shoot`, `mg_shoot`, `gang_dmg`;
- захваты: `capture_try`, `capture_cancel`, `district_capture_try`;
- транспорт/угон: `gta_take`, `gta_enter`, `gta_drive`, `gta_exit`, `gta_status`, `civilian_carjack`;
- банк: `bank_enter`, `bank_exit`, `bank_rob_start`, `bank_rob_announce`, `bank_rob_bag_loaded`, `bank_rob_deliver`, `bank_bag_drop`, `cop_spotted_bag`;
- задания: `brigadir_take`, `brigadir_kill`, `brigadir_claim`, `box_*`;
- сервис: `respawn_status`, `set_respawn_point`, `world_heal`, `race_lap`, `race_top`.

Особенность протокола: большая часть сообщений типизирована строками, без общей схемы/валидатора. Это ускоряет разработку, но повышает риск рассинхронизации при переименовании полей.

## 5. Серверная симуляция `WorldSim`

`WorldSim` — один глобальный объект на процесс. Он хранит:

- `players` и `connections`;
- active event convoy;
- wanted cops;
- territories и district captures;
- aggro zones и covers;
- city gangs и gang nests;
- pending bot shots;
- beachgoers и Michael guards;
- box quests;
- quest cars;
- bank robberies;
- race slots/top.

Тик `_world_run_loop()` работает примерно так:

1. Увеличивает tick.
2. Чистит AFK игроков.
3. Тикает события: конвой, копы, aggro, pending shots, quest cars, beachgoers, Michael guards, gang nests, city gangs.
4. Начисляет награды через SQLite при событиях.
5. Обрабатывает respawn/jail release.
6. Тикает territory/district capture и income.
7. Рассылает event-пакеты.
8. Рассылает `snapshot_for(uid)` каждому подключению.

Сервер авторитетен для:

- HP/смерти в большинстве сетевых боёв;
- тюрьмы;
- wanted;
- денег и наград;
- online-сущностей: cops, aggro bots, gang nests, Michael guards, quest cars;
- захватов и дохода районов;
- валидности персонажа и БД.

Клиент авторитетен или полуавторитетен для:

- локального движения игрока с мягкой серверной коррекцией;
- обычных городских NPC и трафика;
- вождения машины игроком;
- интерьеров зданий/банка;
- части локального урона внутри интерьера;
- визуальных пуль и эффектов.

## 6. База данных

SQLite `mafiozi.db`, доступ через `aiosqlite`. Миграции встроены прямо в `init_db()` через `CREATE TABLE IF NOT EXISTS` и серию `ALTER TABLE ... ADD COLUMN` в `try/except`.

Основные таблицы:

- `characters` — профиль, статы, экономика, внешность, розыск, тюрьма, навыки, jobs, respawn, gang name;
- `inventory` — предметы;
- `active_battles` — активные Telegram/боевые сессии;
- `district_control` — старый/Telegram-контур контроля районов;
- `player_businesses` — бизнесы, доход, статус;
- `gang_members`, `gang_pools`, `friend_collects` — банда и банк банды;
- `pending_notifications` — уведомления для хаба/мира;
- `contacts`, `property_owned`, `apartments_owned`;
- `raid_events`, `coop_sessions`;
- `shop_robs`, `brigadir_kills`, `bank_heists`.

Слабое место: схема живёт внутри одного большого файла, миграции не версионированы. Это удобно для быстрых правок, но трудно понять, какие поля обязательны, а какие исторические.

## 7. Фронтенд открытого мира

`world.html` — Canvas-приложение без фреймворков. Основные слои:

- DOM UI поверх canvas: top bar, sticks, weapon bar, chat, modals, buttons;
- Canvas floor layer: тайлы, трек, периметры, районы;
- depth-sort `items[]`: здания, POI, NPC, машины, игроки, декор, спецэффекты;
- overlay effects: night tint, minimap, feed, target lock, HUD.

Рендер делает важные защитные вещи:

- каждый кадр сбрасывает `ctx.setTransform(...)`, чтобы не копилась поломанная трансформация;
- culling считается от камеры, а не от `player.r/c`;
- draw-вызовы во многих местах уже защищены от падения одного объекта;
- HP-бар и пули приводятся к стилю `demo_isometric.html`.

Ввод:

- левый стик/клавиши — движение;
- правый стик/тап — огонь/прицел;
- в машине левый стик становится газом/рулём;
- режим PvP/PvE выбирается при входе.

## 8. Главные игровые механики мира

### Движение и синхронизация

Клиент предсказывает движение, отправляет `input` примерно 13 Гц. Сервер принимает координаты, clamp-ит карту, ограничивает скорость, учитывает jail. Snapshot мягко корректирует клиента только при больших расхождениях, чтобы не было rubber-band на LTE.

### Машины и GTA-контракты

Есть локальный трафик `CARS`, серверные `questCars`, гражданский угон, топливо, песок/дрифт/ручник, въезд/выезд, пассажирский режим, Майкл на корабле. При вождении клиент считается авторитетным по движению и шлёт `gta_drive`.

### Бой и оружие

Оружие и визуал пуль в `world.html` повторяют/адаптируют `demo_isometric.html`. Урон по серверным целям обычно применяет сервер. Локально рисуются bullets, muzzles, impacts, smoke, hit-stop, camera kick.

### Розыск и тюрьма

Есть два розыска: police wanted stars и gang wanted. Сервер хранит wanted, спавнит world cops, может убить/посадить. Клиентские cityCops тоже существуют и могут отправлять `citycop_arrest`.

### Районы и территории

Есть две похожие системы:

- `TERRITORIES` вокруг POI: market/port/casino/factory/mansion;
- `DISTRICTS` — крупные зоны карты с HQ и доходом.

Обе используют захват, владельцев, income и события. Это мощная, но потенциально дублирующая область.

### Логово, банды, гнёзда

Логово — опасная aggro-зона на юге. Сервер управляет aggro bots, covers, city gangs, gang nests. Личный отряд игрока `_myGang` живёт на клиенте и не равен серверным враждебным бандам.

### Банки

Банк — особенно хрупкая подсистема:

- при входе `player.r/c` становятся локальными координатами интерьера;
- серверу нельзя слать комнатные координаты, поэтому `sendInput()` шлёт `savedR/savedC`;
- `_bankShield()` временно игнорирует серверные hp/dead/jail/cop_shot;
- урон охраны банка локальный через `_hurtLocal`;
- `render()` в банке уходит в `drawBankInteriorScene()` и не рисует общий мир.

Любые правки банка должны сначала проверять координатную модель.

### Случайные события

Есть серверные события: инкассатор, копы, бандитские гнёзда, районные доходы.

Есть локальные события: ДТП, уличная драка, горящая машина.

## 9. Деплой и публикация

Статические файлы публикуются через GitHub API:

- `github_upload_world.py` для `world.html`;
- аналогичные скрипты для hub/creator/graphify;
- `start_with_tunnel.py` публикует `coop_api.json`.

В проектных правилах есть два режима публикации:

- пользователь хочет `git commit` и отправку на GitHub;
- `AGENTS.md` говорит для `world.html` использовать GitHub API upload, а не прямой git push.

Практически: для разработки в репозитории нужен нормальный git commit, но для живого Pages-файла `world.html` всё равно важен `python github_upload_world.py`, потому что он проверяет JS и верифицирует blob.

## 10. Сильные стороны

- Игра уже богата механиками и ощущается как живой open world.
- Очень много защитных комментариев рядом с хрупкими местами.
- Есть `world_index.txt`, `bot_index.txt`, `graphify.json` для навигации по монолитам.
- Есть проверка JS через `check_world.py` и публикация с верификацией.
- Серверная симуляция на 15 Гц достаточно понятна: один мир, один тик, снапшоты.
- В `world.html` много уже решённых проблем: rubber-band, camera culling, ctx transform reset, local bank shield, NaN/сломанные draw-объекты.

## 11. Слабые места и риски

### 1. Два огромных монолита

`world.html` и `mafiozi_bot.py` слишком велики. Новая функция часто цепляет карту, UI, WS, БД и рендер одновременно. Риск случайно сломать соседнюю механику высокий.

### 2. Дублирование констант между JS и Python

Карта, трек, южная зона, jail, districts, weapons и POI частично продублированы. Ошибка в одной стороне даёт рассинхрон: клиент рисует проходимый тайл, сервер считает стеной, или наоборот.

### 3. Нет формальной схемы WS-пакетов

Пакеты описаны строковыми `t/kind` и произвольными полями. При изменении названия поля нет автоматической проверки клиента и сервера.

### 4. БД-миграции не версионированы

`ALTER TABLE` в `try/except` решает быстрые добавления, но не даёт истории схемы, rollback и проверки целостности.

### 5. Смешение локального и серверного авторитета

Это главный источник багов мира. Например, банк, машина и тюрьма имеют специальные исключения из snapshot reconciliation. Новые механики легко забывают эти исключения.

### 6. Дублирующиеся системы районов

`TERRITORIES` и `DISTRICTS` похожи по смыслу. Пока они дают разные уровни геймплея, но для игрока и для кода это может стать путаницей: что именно захватывается, что даёт доход, где PvP легален.

### 7. Тесты в основном синтаксические

Есть `node --check` и `ast.parse`, но почти нет поведенческих тестов: карта, WS-пакеты, `WorldSim.tick_*`, банк, jail, race lap, capture.

### 8. Грязное рабочее дерево

На момент анализа в рабочем дереве уже есть изменения в `.gitignore`, `mafiozi_bot.py`, `world.html`, `world_index.txt` и много untracked служебных/случайных файлов. Это повышает риск случайно закоммитить мусор или чужие изменения.

## 12. Рекомендации по улучшению

### Ближайшие, без ломки архитектуры

1. Ввести файл `WORLD_CONTRACT.md` или раздел в `PROJECT_ANALYSIS.md` со списком WS `t`/`kind`, обязательных полей и владельца состояния.
2. Добавить маленький скрипт проверки синхронности констант: `MAP_ROWS`, `MAP_COLS`, beach/pier/ship, race points, jail, district HQ.
3. Перед каждой правкой `world.html` запускать минимум:
   - `python check_world.py`
   - `python check_bot.py`, если трогался сервер
4. Обновлять `world_index.txt` и `bot_index.txt` после крупных правок через `gen_index.py` и `gen_index_bot.py`.
5. Добавить `.gitignore`/чистку для случайных файлов с именами вроде `140)`, `{,+`, `MAP_ROWS`, если они не нужны.

### Среднесрочные

1. Вынести из `world.html` хотя бы конфиги в отдельные JS-блоки или генерируемый JSON:
   - карта/юг/трек;
   - оружие;
   - POI/business/districts;
   - тексты/фразы.
2. Сделать общий источник правды для карты между Python и JS. Например, маленький `world_config.json`, из которого генерируются JS/Python константы.
3. Разделить `WorldSim` внутри `mafiozi_bot.py` на логические классы без изменения внешнего API:
   - cops/wanted;
   - capture/districts;
   - aggro/gang nests;
   - quest cars/Michael;
   - bank;
   - race.
4. Добавить unit-тесты на чистые функции:
   - `_world_is_wall`;
   - `_build_track_tiles`;
   - capture state transitions;
   - `apply_input`;
   - jail clamp/release;
   - income payout.

### Долгосрочные

1. Постепенно перевести `world.html` из одного файла в сборку без npm-runtime в игре: исходники можно держать модульно, а публиковать один собранный `world.html`.
2. Ввести версионированные миграции SQLite.
3. Сформировать replay/debug режим для `WorldSim`: запись входящих WS-пакетов и воспроизведение проблемных сессий.
4. Сделать dev-режим локального мира: статический сервер + локальный `mafiozi_bot.py` + тестовый пользователь без Telegram.

- Перед правкой смотреть `git log -1`.
- Сначала найти существующую подсистему по `world_index.txt` и `rg`, затем править рядом с ней.
- Если меняется геометрия мира, проверять Python-дубликат в `WorldSim`.
- Если меняется WS-сообщение, править обе стороны и документировать поле.
- Если игрок входит в интерьер, не слать серверу локальные координаты комнаты.
- Если меняется машина/пляж/гонка, сверять песок, `_inPitCorridor`, трек и серверный clamp.
- Если меняется бой/оружие/HP, сверяться с `demo_isometric.html`.
- Не добавлять вторую параллельную систему, если уже есть похожая.

## 14. Самый важный вывод

Сейчас проект развивается вокруг `world.html`: это главный продуктовый экран и самая хрупкая часть системы. Архитектуру нельзя «резко улучшить» одним большим рефакторингом. Правильный путь — маленькие точные изменения, обязательная синхронизация JS/Python констант, проверка `check_world.py`, и постепенное выделение контрактов/конфигов вокруг уже работающего монолита.
