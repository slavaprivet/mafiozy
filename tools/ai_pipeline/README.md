# Экономный исследовательский процесс — MVP

Координатор 17 отвечает за постановку, владение файлами, проверку и интеграцию.
Пять профилей в profiles.json — библиотека заданий, а не постоянно работающие агенты.
Пользователь 16 сентября выбрал начать с трёх обычных Chat с Astra, создаваемых
им в интерфейсе. Платный DeepSeek остаётся отключённым до отдельного согласования.

## Что уже делает инструмент

- Собирает только перечисленные текстовые файлы целиком, без молчаливого обрезания.
- Сохраняет ветку, HEAD, статус выбранных файлов и SHA-256 каждого файла, включая
  незакоммиченные изменения. Повторно проверяет актуальность перед/после работы.
- Готовит самодостаточное задание для обычного Chat без API или копирования истории.
- Выполняет только существующие проверки из доверенной конфигурации; результаты
  на том же снимке прикладываются к следующему пакету. Это не автоматическая
  проверка любой игры и не доказательство FPS.
- Валидирует строгий формат отчёта и ограничивает патч указанными файлами.
- Проверяет применимость и применяет предложенный diff только в отдельной копии.
  Сгенерированный код не запускает. Отдельная копия не является песочницей.
- Опциональный адаптер использует официальный DeepSeek chat-completions API.
  Нет автоматических повторов, переключений модели или рекурсивных агентов.

## Один обычный запуск

Из корня проекта, PowerShell:

```powershell
./tools/ai_pipeline/run.ps1 mock
```

`prepare` сохраняет контекст; `baseline` запускает существующую CPU-проверку травы;
`test` проверяет сам инструмент; `status` показывает фактические API-попытки.
Все команды кроме явного `live` обходятся без внешних модельных вызовов.
Вызов инструментов и чтение результата координатором всё равно расходуют его работу.

Для координатора: `pipeline.py chat-pack --task <task.json>` создаёт Markdown-пакет.
Файл можно передать целиком в обычный Chat. Название/модель нового Chat выбирает
пользователь в интерфейсе; инструмент не имитирует создание и закрепление чатов.
Ответ сохраняется как JSON, затем `pipeline.py review --task <task.json> --response
<reply.json>` проверяет схему, точный SNAPSHOT_ID и применимость diff в отдельной
копии. Код ответа не исполняется; при изменившихся исходниках ответ отклоняется.

Подготовлены непересекающиеся задания:

| Чат | Конкретное задание |
|---|---|
| Астра 1 — Оптимизация | Проверка выбора травы и обновлений буферов, существующие тесты и исторические замеры |
| Астра 2 — NPC и мир | Жизненный цикл наёмника: падение, больница, возврат, увольнение и незавершённые действия |
| Астра 3 — Проверка | Независимое ревью диспетчера: границы контекста, бюджет, ошибки API, проверка патчей |

Каждый Chat получает одно законченное задание, работает по предоставленному тексту,
не переключается в Work и не создаёт собственных агентов. Повтор — только по
конкретному пробелу/дефекту, максимум один дополнительный модельный ответ на задачу
в начальном пилоте. Обычный Chat имеет собственные условия использования;
бесплатность или отсутствие всех лимитов не обещаны. Ответы проверяет координатор.

## Локальное хранение и внешние обращения

Обновление формата: `chat_output_policy.txt` задаёт приоритет полного результата
в доступном штатном файле/документе обычного Chat, в сообщении — до 8 коротких строк.
Если файл создать нельзя, Chat сообщает ограничение и даёт итог до 1500 знаков;
это краткая передача, а не полный отчёт. Не переключать его в Work ради файла.

`chat_notebook.py <read_thread-export.json>` сохраняет только agentMessage,
пропускает пользовательские исходники и дублирующий thread.preview. Полный текст
остаётся на диске, stdout ограничен короткими квитанциями. Повторные чтения
не размножают записи. Обрезанные ответы явно помечаются и не считаются JSON-отчётом.
Скрипт работает по вызову координатора, без фонового опроса или сообщений моделям.
Блокноты: `docs/ai/ASTRA_NOTEBOOK.md`; пять тестов архиватора пройдены.

Пакеты, ответы, диагностика и журнал находятся в `git-common-dir/ai-pipeline-local/`.
В этой рабочей копии это `.git/ai-pipeline-local/`, вне отслеживаемого исходного кода.
Никакие секреты не сохраняются в пакетах. Проверка паттернов секретов — защита
от распространённых случайных утечек, не полное распознавание любых персональных данных.
Перед первой внешней отправкой координатор просматривает конкретный набор файлов.

`live` требует одновременно ключ в окружении процесса и локальный `approval.json`.
Координатор создаёт этот файл только после явного согласия пользователя на провайдера,
область кода, бюджет и число обращений. Формат:

```json
{
  "provider": "deepseek",
  "model": "deepseek-flash",
  "snapshot_id": "точный snapshot_id проверенного пакета",
  "allow_external_code": true,
  "expires_on": "дата согласованного окончания YYYY-MM-DD",
  "task_usd": 0.1,
  "period_usd": 0.5,
  "max_calls": 2
}
```

Пример не является выданным разрешением. При необходимости пользователь запускает
`./tools/ai_pipeline/run.ps1 live` и вводит ключ скрыто в локальном терминале.
Ключ живёт только в окружении процесса на время запуска; прежнее значение
восстанавливается. Не присылать ключ сообщением и не помещать в исходники.

Каждая API-попытка резервируется до сети и учитывается даже после ошибки/timeout/crash.
Журнал общий для worktree одного репозитория, сохраняется между запусками.
Параллелизм 1 через исключительную блокировку. После аварийного завершения
оставшийся run.lock требует проверки процесса владельца; не удалять его вслепую.
Месячный период считается по UTC. На TASK_ID не более двух API-попыток, включая
ошибки; смена TASK_ID не обнуляет общий бюджет. Не использовать новый ID ради
обхода лимита. Расход обычных Chat учитывается координатором отдельно, не выдаётся
за измеренный расход этого API-журнала.

Расчёт использует завышенную оценку входа по байтам и максимальный выход.
Успешный ответ сохраняет фактические prompt/completion tokens; оценка цены использует
верхний тариф без скидки кеша. Резерв не возвращается автоматически. Это локальное
ограничение допуска запросов, не гарантированный лимит списаний провайдера.
Цены старше 7 дней блокируют live до перепроверки. Расход Work и процент экономии
не измерены. Разовая настройка и дальнейшее использование оцениваются отдельно.

## Выбор подключения и источники — проверено 16 сентября 2026

Выбран небольшой Python-инструмент со стандартной библиотекой: явные бюджеты,
mock-тесты, независимость от настроек координатора и возможность позже обернуть
те же функции MCP-инструментом. Собственный сервер/MCP сейчас не нужен.

Проверены альтернативы: конфигурация Codex описывает custom providers с протоколом
Responses; DeepSeek сейчас также документирует Responses. Это само по себе не
доказывает доступность переключения текущей задачи/обычных Chat. Настройки не менялись.
В доступных инструментах есть создание Codex/Work задач и отправка в существующий
Chat, но нет создания обычного Chat и выбора его модели. ToolSearch/Ruflo не доступны.

- [Codex configuration](https://learn.chatgpt.com/docs/config-file/config-reference)
- [DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)
- [DeepSeek JSON output](https://api-docs.deepseek.com/guides/json_mode/)
- [DeepSeek models and pricing](https://api-docs.deepseek.com/quick_start/pricing/)

Открытая страница документации указала `deepseek-flash`; поисковый кеш ещё показывал
старые имена/цены. Конфигурация основана на открытой странице, не на поисковом сниппете.

## Что ещё не принято

Нет реального DeepSeek smoke test, внешнего исследовательского результата и принятого
игрового патча от этого процесса. Нет подтверждённой изолированной среды исполнения
сгенерированного кода; такие тесты блокируются до отдельного выбора среды/ревью.
Нет новых LIVE-замеров игры, доказанной экономии лимита и автономной фоновой работы.
Существующие изменения игры, незавершённые правки других авторов и Git index не менялись.
