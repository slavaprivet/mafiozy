## Visual and runtime authority gates

The frozen station_texture_adapter consumes the actual original Windows Arial
Bold browser canvas captures, source receipts and SHA hashes. Base1024x192 RGBA
pixels retain exact one-row-flip interpretation, original Plane UVs,11 mip
levels, linear-mipmap-linear/clamp/anisotropy1. Its original material clone is
installed with the explicit original sampler; PBR values are unchanged.

Exact base pixel/source evidence does NOT prove original GPU driver mipmap
bytes, angled/distant appearance, shaders/shadows/lighting or general FPS.
Default fixture.visual_approved=false means railway remains HOLD; both tests
explicitly assert this default leaves no fake partial railway scene. Only a
trusted host visual owner Callable may admit CPU mip/sampler candidate. The
included rail_fixture.gd and gameplay edit callbacks are TEST FIXTURES, not a
production visual/route/collider owner. Do not deploy that approval as actual
GPU acceptance. No train/signal motion adapter is connected by these tests.

Real runtime owner must keep work paused during whole import, rebuild source
rail/crossing/parking routes, collisions, ownership and signals, and approve
commit/rollback before resuming. A geometry admission cannot self-authorize
these mechanisms. Native source records, railway sourcePlan/car transforms,
station IDs, bay/access/routing metadata and original train asset SHA remain
unchanged. No user flag is an authority token.

Rail clone is still explicit HOLD. Duplicating a canonical route/train requires
an independent trusted owner allocating new route/geometry IDs and authority;
V2 never pretends a static clone has that permission. Parking clone works via
original trusted source template as in V1; this is not a full map-editor claim.
