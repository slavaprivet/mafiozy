# Navigation editor-pause receipt seam — source-only, not K admission

This candidate pins the actual 2026-09-30 `preview_engine_navigation.gd`, `preview_navigation_host.gd`, queue and interior dependencies. `pause_backend.gd` subclasses the real engine backend; the builder derives both host **and queue** from exact pinned owner sources. Current source-only seam adds `can_end_editor_pause` to all three owners, with a read-only unpaused preflight that does not release a lease, advance the queue clock, or replay a callback. The checkpoint resident stage overlays all three nav owners from the same source pins. Production files and the running game are untouched. **Current version has no Godot import/native result.** Earlier isolated native `22 checks, failures=[]` and stage `outputs/map-editor-nav-pause-uRHkI1` predate queue ownership and `can_end`; they are historical evidence only, not validation of this revision. No LIVE or default-residents K readiness is claimed.

The backend pause receipt is tied to the real owner Node instance, authority, generation, source version, epoch, native map/region RIDs, map iteration, bake token, waiting snapshot, job count and next-job counter. Admission refuses any live backend job/owner ledger or host path record until exact mutable job-content receipts exist. The queue requires an idle ledger and pins its clock callable, frame, counters, stats and state; its `reserve`, `finish`, `expired`, `cancel` and diagnostics entry points are gated during the lease. Async `_finish_bake` and stale `_finish_query` completions are retained (bounded to 256) and do not publish a map or mutate a path job during the lease. New publish, path request, pump, motion admission, poll and cancellation return refusal and fault the lease. On exact resume, the host releases the queue first (that release does not invoke callbacks), then backend replays retained completions through the original implementation. This avoids replay into a still-frozen queue. A late backend refusal *after* queue release remains non-atomic and enters terminal HOLD; a main/root transaction and native proof are still needed. Overflow, source drift, map-iteration change, owner queued for deletion/destruction or a foreign write cause HOLD; only teardown may discard an overflowed completion. The derived host also guards door/access changes and native request/step/pump. It requires both real printshop doors to have `fraction == target` at admission and checks fraction, target, pivot identity/transform and collision leaves at verification. A direct interior `request_door` can still change target while the tree is paused; verification detects a currently changed target, but only a future interior command revision/lease can detect an A→B→A command history. The old small native fixture exercised only the predecessor backend seam and early host guards; its new queue/preflight cases are unrun.

This is deliberately a **narrow owner seam**. Actual `PreviewPopulation` still preloads the production navigation and resident classes; it does not instantiate this derived host. `preview_resident_host.gd` can independently mutate body/gait/status/preview-walk clock in `step`, `preview_walk_step`, placement and disposal. Root must not wire K merely by swapping a preload. The NPC owner must add a population-level lease that composes navigation and resident receipts, blocks every mutator, captures actor body transforms, velocity, status, gait and life generation, and verifies scene/source ownership. The root must then compose that receipt with player, transport, melee, water and input leases in one main-thread K transaction. Unpause plus `end_editor_pause` must be synchronous before the next physics tick; failure re-pauses/HOLD rather than running residents with a frozen nav lease. Root-only actual main/GPU/LIVE authority remains unchanged.
