# Authored 242 read-only incremental native builder (unrun candidate)

This is executable Godot code plus an opt-in native fixture, **not** a production main patch, K admission, full 9901 renderer, editor operation, or FPS result. The source is the immutable Coordinator22 residents checkpoint and the exact canonical activation manifest SHA `47c8fd105dea7b87d12c63eeb0e5c10373c9832e947def2ac870f1618996d08c`.

`authored_readonly_builder.gd` loads the SHA-pinned catalog and activation manifest from the staged project, configures the frozen authored `catalog_factory.gd`, and walks exactly 242 resource-backed source rows. `step(1, 2000)` constructs at most one original GLB source object per call. Roots stay under an invisible, separate preview container until exact 242-key and 242-unique-root coverage completes. The factory verifies raw resource bytes and SHA before native `PackedScene` load; the builder rejects an absent import, null mesh/surface, or absent imported material when the catalog declares materials. It requests no exterior collisions and rejects any gameplay-active/collider result. Three bank shells and three detention records retain their owner-pending status; source visuals are not edit or gameplay admission. `close()` frees only preview-owned roots.

The builder accepts only `borrow_live: bool`, never a caller-supplied root dictionary. With `borrow_live=true`, it invokes the script-pinned `live_authored_owner.gd` against the actual checkpoint main. That owner checks actual `main.gd`/`block.json` SHA, all 16 ID/model/transform/source-resource mappings, canonical scene registry, root uniqueness, and ordinary mesh/material tree equality. It refuses active static batching. Its result currently **HOLDs all-16 borrowing**: Printshop's interior owner intentionally replaces/hides original meshes and creates doors/parts, so a separate exact interior receipt is required. The owner audits the other 15 ordinary roots but does not return a partial root set as full coverage. Thus this builder is **not mountable alongside actual main without duplication** yet. The current fixture uses an independent `SceneTree` and proves source visuals only; it does not claim actual-main/K integration or edit authority.

It checks the complete checkpoint path/byte set twice, source pins, activation manifest and all 196 GLB source hashes/path sets. No stage or Godot run is implied by dry-run.

After Coordinator22 grants a CPU window, `node tools/godot/map_editor_authored_incremental_candidate/stage_checkpoint.mjs --stage` creates a unique outputs-only Godot project with the original checkpoint settings except a unique user directory. Then import it headlessly and run `res://test_authored_readonly_builder.gd` sequentially; inspect engine diagnostics even on exit 0. The fixture checks an invalid borrowed identity, one object per step, exact 242/196 coverage, unique native roots, read-only status, and cleanup. **No Godot/import/headless/GPU was run in this candidate yet.**

The per-step object-count bound is hard; `max_usec` is a cooperative limit checked between whole GLB instantiations, not a preemptive maximum for a single imported resource. The returned `budget_exceeded`, `max_step_usec`, and step count must be measured before any frame-time claim. Materials/meshes are checked for presence, not pixel parity; no collision, terrain, water, nav, traffic, resident, protected edit, persistence, or whole-world authority is admitted here. Production installation of the 196 canonical resources and real pause-owner receipts remain separate gates.
