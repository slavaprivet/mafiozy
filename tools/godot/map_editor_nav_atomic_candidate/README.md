# Navigation atomic-resume source candidate (HOLD)

This builds only derived source for the pinned navigation backend, queue, and host. It does not modify `godot/mafiozi_walk`, start Godot, or authorize K in the production game.

Public host protocol: `prepare_editor_resume_atomic(receipt) -> Dictionary`, `commit_editor_resume_atomic(ticket) -> Dictionary`, `abort_editor_resume_atomic(ticket) -> bool`, `finalize_editor_resume_atomic(ticket) -> bool`. The first three retain the paused lease. `finalize` releases queue/backend/host guards synchronously while `SceneTree.paused` remains true, but the backend continues holding bake/query completions. After **all** global owners have finalized, the root unpauses and calls `flush_editor_resume_atomic(ticket)` to replay held completions. The backend keeps a weak reference to the original root until flush and refuses replay if that owner has changed or the tree is still paused. The legacy one-shot `end_editor_pause` is disabled. `cancel_editor_pause(receipt)` is only for rollback *before* the root pauses the tree; it refuses when completions are held.

No yield/event-loop turn may occur between final global preflight, commits, finalizers, root unpause, and flush. The same main-thread call stack is required. If any prepare/commit fails, abort all tickets and keep the paused leases; if a late child finalizer or flush fails, terminal HOLD is mandatory. Queue releases before backend because callback replay can admit via the queue; replay occurs only after all resident/policy owners are released.

Late-flush protection: the backend rejects a second pause or external writes while flush is pending, and retains the callback guard through replay. A reentrant completion joins the held queue. Replay pops a callback before invoking it, checks owner/ticket/fault after each callback, and caps the entire batch at 256 (including reentrant additions). Failure preserves the unprocessed tail and faults the ticket; retry is refused. Already-invoked callbacks cannot be rolled back, so a partial replay is terminal HOLD, not an atomic success. An engine callback with side effects outside this backend remains a native integration risk.

Current proof: `node tools/godot/map_editor_nav_atomic_candidate/test_source.mjs` checks source shape, pinned derivation, and negative source mutations for early guard release, replay duplication, unbounded reentrancy, and missing post-callback checks. `node tools/godot/map_editor_nav_atomic_candidate/stage_native_fixture.mjs` stages the pinned candidate and read-only navigation dependencies inside this folder. Running Godot 4.7.2 console with `--headless --path tools/godot/map_editor_nav_atomic_candidate/fixture --quit-after 600 --script res://test_late_flush.gd` passed 23/23 checks: late completions remain held after unpause, ordinary replay succeeds, and a first callback's side effect plus guarded-write fault leaves the unreplayed tail held and refuses retry. This is a focused backend seam fixture. Actual owner composition, asynchronous map-iteration behavior, LIVE FPS, and engine-level atomicity against independent NavigationServer mutation remain unverified; keep the production K gate closed until root integration verifies those cases.
