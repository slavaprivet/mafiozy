## 2. Два подтверждённых замечания к коду

### D1 — маркер READY не подтверждает успешную загрузку квартала

**Функции:** `main.gd::_ready()` и `_add_asset()`.

При `load(record["path"]) == null` функция `_add_asset()` сообщает ошибку и возвращается. `_ready()` не получает результат отказа, продолжает сборку и в конце печатает `MAFIOZI_PREVIEW_READY`, используя **заявленные числа из `block["counts"]`**, а не фактически успешно созданные объекты. Проверка успешной загрузки героя перед этим маркером также отсутствует. Это подтверждённая ветка исходника; fault injection в Godot здесь **не выполнялся**. 

**Независимая приёмка `S01-A03`:** в изолированном fixture испортить путь четвёртого здания; отдельно проверить missing hero, неизвестную схему, повтор ID и невалидный collider.

**Обязательный результат:** нет `READY/ACTIVE`, нет принятого неполного квартала. При первом запуске — явный `FAILED`; при наличии предыдущего активного мира — он остаётся неизменным. Проверять реальные `loaded/failed/model_loaded`. Предварительная проверка exporter не заменяет проверку отказа потребителя.

**Владелец исправления — Root20.** Новую реализацию загрузчика я не создавал.

### D2 — физическая поза героя записывается из двух разных циклов

**Функции:** `main.gd::_process()` и `preview_player.gd::_physics_process()`.

Player motor меняет движение в физическом цикле, но `main._process()` при `position.y < -12` напрямую меняет **и позицию, и скорость**. Это нарушение целевого договора единственного владельца физического состояния. **Это не заявление о доказанной многопоточной гонке или наблюдавшемся дрожании:** runtime-проверки не проводились. 

**Независимая приёмка `S01-A04`:** падение ниже порога при render 30/60/120/144 FPS, кадрах без physics tick, stall 250 мс и потере фокуса.

**Обязательный результат:** respawn поступает как запрос, motor применяет `pose + velocity` **один раз на физической границе**. При включённой интерполяции — её корректный сброс. Рендер не становится вторым владельцем физической позы.

## 3. Что именно блокирует S00

**Существующий sourceS00 сохраняем — повторно его создавать не требуется.** Документ Root20 уже различает исторический HEAD, локальный service WIP и непринятые proposals. Но он прямо сообщает, что S00 не закрыт: нужны full-host snapshot и сопоставимый тяжёлый игровой маршрут. 

| Gate | Что уже установлено | Что требуется для закрытия |
|---|---|---|
| **Происхождение исходников** | Historical baseline и новый preview разделены; WIP описан отдельно | Закреплённый incoming ledger с решением по каждому пакету и его фактическому включению |
| **Целостность sourceS00** | Root20 сообщает о проверке 711 членов ZIP | Предоставить существующие `manifest.json` и `source_snapshot.zip` для независимого чтения. По указанному пути на закреплённом GitHub ref архив мне недоступен |
| **Full-host snapshot** | `block.json` сохраняет `pendingHostSnapshot: true` | Согласованный результат после `buildMap` и сборки Walk, а не только исходные placement-файлы |
| **Authority** | Есть содержательная таблица источников и владельцев | Проверяемая матрица по доменам и режимам offline/authenticated, включая границы передачи управления |
| **Baseline/performance** | Есть сообщённое оборудование и отдельные исторические измерения | Raw traces эталонных маршрутов, точные настройки и принятые бюджеты RAM/VRAM |

Эти ограничения зафиксированы в документах S00 и в самом preview manifest; их нельзя закрыть только успешным импортом моделей. 

### Full-host snapshot — конкретный критерий

В новом JSON задан обязательный состав capture. Он должен учитывать **четыре входа**: topology, buildings placement, decor placement и detention native sites; затем — фактически построенные terrain, railway, интерьеры, этажи, лестницы, двери, окна, входы и коллизии. Именно такое расширение исходных данных описано в S00 Root20. 

Для приёмки требую связать результат с `source_lock`, принятыми WIP-хешами, `map_revision`, `world_epoch`, `assembly_generation` и доказательством согласованности capture. **Список видимых NPC/машин не заменяет полный авторитетный список сущностей.** При неизвестных секциях или несовпавших ревизиях — `complete=false`, с перечислением пробелов.

Source ZIP, лексический граф импортов и восьмидомный `block.json` остаются полезными артефактами, но **не подменяют full-host snapshot**.

### Authority gate — не требование немедленно реализовать всю игру

Для S00 требуется установить, **кто уже владеет состоянием в исходной игре**, отдельно для offline и authenticated. Для каждой строки: домен, сущность, source symbol, authoritative writer, вход команды, граница commit, epoch/revision, readers, правила prediction/dedupe/cancel.

Отсутствие HP, денег или мест автомобиля в маленьком preview не доказывает корректность будущей серверной authority. Исходный S00 как раз предупреждает, что один общий договор «Godot владеет всем» был бы неверным.

## 4. S01: маленький debugprobe не равен принятому стенду

В проверенном `project.godot` стоят **Compatibility, 1280×720, physics 60 Гц**. В журнале Root20 сообщаются **144 FPS, p95 delta ≈6,9 мс, ≈1016 draw calls и 188168 primitives** для неподвижного debug-квартала. Сам журнал правильно ограничивает эти данные: не экспорт приложения и не городской gameplay FPS. 

**В этой приёмке:**

```json
{
  "root_debug_probe": "REPORTED_NOT_REPRODUCED",
  "independent_godot_runtime": "NOT_RUN",
  "independent_gpu_timing": "NOT_RUN",
  "release_benchmark": "NOT_RUN",
  "full_walk_gameplay_performance": "NOT_RUN",
  "gpu_ms": null
}
```

`main.gd` собирает `delta` в небольшой буфер и выводит p95; это не самостоятельный GPU-таймер. Снятие изображения viewport выполняется отдельной диагностической веткой, поэтому будущий timed run должен отключать screenshot capture либо явно отделять его от измеряемого интервала. 

**Для закрытия S01 нужны:** exact engine/template lock, самостоятельная release-сборка стенда, фактические renderer/driver/backend, пригодный trace contract, проверки отказов/повторного boot и изоляция от реального прогресса. Текущий launcher запускает проект через `--path`; это не свидетельство наличия экспортированной release-сборки. 

**60 Гц не объявляю ошибкой.** Исторический план допускает проверенный выбор 60 или 120 Гц. Сейчас требуется решение с доказательствами, а не безусловное переключение на 120 или другой renderer.

**Полный NPC/traffic/combat ещё не требуется реализовать ради приёмки S01.** Проверяется стенд на заявленном содержимом. В матрице `MILESTONE-A01.blocks_acceptance=false` относится **только к текущей приёмке S00/S01**; для соответствующих дальнейших milestones performance gate остаётся обязательным. Нереализованные сценарии — `NOT_IMPLEMENTED`, не `PASS`.

## 5. Команды независимой проверки — без запуска игры

Сохранить `codechecks.py` в отдельном каталоге проверки. Указать существующий локальный репозиторий:

```powershell
$Repo = "C:\путь\к\mafiozy"

python -B .\codechecks.py --self-test
python -B .\codechecks.py --repo $Repo
```

Для дополнительной проверки **уже созданного** sourceS00, когда Root20 предоставит оригинальный каталог:

```powershell
python -B .\codechecks.py --repo $Repo --s00-dir (Join-Path $Repo "outputs/godot_s00_20260926_final")
```

Checker проверяет происхождение commit, закреплённые Git blob IDs, receipts исходных JSON, копии GLB, IDs, трансформации, происхождение коллизий и crop масок. Он **не** проверяет исполнение Godot, визуальное соответствие и FPS.

**Не запускать повторный capture и не откатывать HEAD ради `EXPECTED_HEAD=3612…`.** Это намеренное ограничение исторического capture-скрипта; его `--verify` проверяет существующий архив отдельно от создания нового. 

При несовпадении raw hashes сохраняется ошибка проверки. Нельзя автоматически нормализовать данные, обновлять ожидаемые SHA или подмешивать WIP, чтобы получить зелёный результат.
