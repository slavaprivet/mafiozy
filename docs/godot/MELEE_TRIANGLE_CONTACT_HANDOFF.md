# Native precise melee triangle contact

`scripts/combat/melee_triangle_contact.gd` SHA-256
`b8e651faa13affa83436bb59fe169c1b23d6dc0344126f78dbb6deca5586ac9b`
ports the closest swept segment / posed triangle math from the actual
`npc_melee_contact.mjs` source. It is a pure component, not connected gameplay.

`sample(from, to, radius, a, b, c)` returns an explicit valid/hit result,
surface point, limb-line point, outward normal, barycentric anchor, squared
distance and original source ranking score. Positions are native world metres;
the caller supplies current posed vertices. It rejects nonfinite/out-of-range
inputs, preserves source degenerate-face misses and strict closest-point tie
ordering. All intermediate vector operations use float64; conversion to Godot
Vector3 occurs only at the boundary. Float32 intermediate determinants caused
wrong edge winners and incorrect/nonfinite anchors on narrow faces.

The unchanged full original JS / Three180 / SkinnedMesh oracle is generated by
`tools/godot/build_melee_triangle_oracle.mjs`. Source SHA is
`7897c26dbfd541e0170bea6cacb7924d6ac20675782103be8da532d31f6e001c`.
It has 288 cases, including 80 hits, transformed/nonuniformly scaled geometry
and degenerate faces. Original suite: 902 checks PASS, maximum surface error
1.012 micrometres. Independent analytical suite: 189 checks PASS. The committed
suite additionally retains the independently confirmed thin-face and parallel
edge regressions. Source oracle and original tolerances were not weakened.

## Performance gate — currently held

Independent actual hero measurements use 8,338 vertices / 13,034 triangles,
48 warmed samples per case after per-triangle AABB filtering:

| Sweep | Candidate triangles | Kernel batch p50 / p95 ms |
| --- | ---: | ---: |
| Head, radius .10 | 770 | 40.659 / 46.785 |
| Head, radius .14 | 1,483 | 73.018 / 77.929 |
| Chest | 431 | 21.784 / 25.882 |
| Forearm | 228 | 11.327 / 12.278 |
| Shin | 72 | 3.727 / 6.233 |

Therefore naive per-frame AABB scan followed by this kernel for every candidate
is **not accepted for production**. These are component CPU costs, not loaded
scene FPS. Root subsequently removed temporary arrays by expanding the same
float64 operations into scalar arithmetic. All922 committed checks and189
independent checks still PASS; maximum source point error is unchanged.
Same actual topology and48 warmed samples: head radius.10 p50/p95
14.374/18.419ms, head radius.14 27.949/32.255ms, chest.10 7.957/8.772ms,
forearm.10 4.215/4.875ms, shin.10 1.372/1.572ms. These are separate runs,
not an alternating paired benchmark; old results are preserved as
`cost_0fd6_baseline.json`, intermediate as `cost_bf08_intermediate.json`,
final as `cost.json`. Even this speedup does not admit the naive per-frame path.
A conservative topology hierarchy/current-pose refit and exact
ranking-preserving pruning are being evaluated separately. They must include
their own geometry/refit cost and cannot turn unfinished work into a miss.
Evidence: `outputs/coordinator21_melee_triangle_review/REVIEW.md` and `cost.json`.

Current-pose geometry, pose/life/mesh identity, sweep windows, actual obstacle
occlusion, source target/damage/medical/death authority and measured physical
impulse remain caller responsibilities. A positive triangle sample alone must
never change HP or apply an impulse. The sole interactive physics19 game is
unchanged by this component.
