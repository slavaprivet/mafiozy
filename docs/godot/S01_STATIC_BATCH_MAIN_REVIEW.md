## Verified behavior

- Default OFF publishes `disabled`, has no lease, empty plan summary and no generated static batches. Code inspection confirms the opt-in call is after asset construction and before player creation/readiness.
- ON retains every original node ID, parent/path/type and `source_id`/`source_index`; original mesh/material resource identities, world transforms, layers, shadow and GI settings remain equal. Physical RIDs, node/shape identities, shape storage properties, collision layers/masks, disabled flags and world transforms remain equal.
- Exactly 248 previously visible source leaves become hidden. Their 69 batches remain under the explicit approved owners. Repeat apply is idempotent.
- Both OFF and ON receive real E press/release events at the public printshop entrance. The original controller capsule is blocked while the door is closed, passes the real open doorway cast, and is blocked again after E closes it. The service door remains closed. The complete printshop hierarchy returns to exactly the original transforms/visibility, and physical snapshots remain equal after the closed cycle.
- Restore reinstates exact original local visibility/resources/physics and frees all first-generation batch node IDs, including when the test retains the lease. Double restore is harmless.
- An OmniLight3D is added **only after restore**. The next apply rejects the changed lighting contract with explicit fallback status, while main remains ready and all original geometry/physics remains present. Removing the light permits an explicit rebuild.
- Freeing the active main invalidates all original and generated node IDs and leaves a retained lease with empty batch nodes and receipts. Separate startup ON succeeds; a separate startup with a pre-existing local light fails closed, remains ready, publishes errors and retains the same canonical original visibility without partial batches.
- Main/helper hashes remain unchanged between test start and completion.

Generated unnamed nodes have process-global names in Godot. Cross-instance visibility comparisons normalize only those autogenerated path segments to class plus unchanged sibling index; same-instance identity/hierarchy checks use exact instance IDs and paths. The first test draft exposed this fixture naming issue and missing-metadata defaults; only the test was corrected. No production finding remained after the final run.
