# Продавцы: кладовка и служебная дверь

26 сентября 2026. Требование пользователя для исходного Walk и переноса в Godot.

## Обязательное поведение

В каждом обслуживаемом здании предусмотрены отдельная кладовка и физическая служебная дверь. Рабочее место продавца связано с постоянным ID здания, кассой и точками подхода покупателей. Размещение проверяется отдельно для каждого интерьера; один универсальный якорь не считается корректной интеграцией.

Пока продавец мёртв, покупки и услуги недоступны: нет списания денег, выдачи товара или фиктивной квитанции. Тело сохраняет свой жизненный цикл. Через 60 секунд создаётся новый сотрудник с новым ID внутри кладовки. При видимой игроку точке появления, занятом проходе или непроверенной геометрии выход откладывается. Новый сотрудник открывает дверь, физически проходит проём, закрывает её после освобождения проёма и подходит к рабочему месту. Обслуживание включается только после фактического прибытия живого сотрудника.

Продавец остаётся обычным живым NPC: получает урон, реагирует на угрозы, зовёт полицию, может прервать работу. Возврат после тревоги проходит физическим маршрутом. Остановка обслуживания и отмена покупки не создают повторных списаний или товаров.

## Проверка перед приёмкой

- Обычный выход из кладовки: движение двери, коллизии, положение стоп, отсутствие телепортации.
- Смерть во время обслуживания и выхода: старые callbacks не управляют новым сотрудником; покупка отменяется без потерь.
- Не менее 60 секунд до нового сотрудника; новый ID, прежнее здание, сохранённое старое тело.
- Игрок смотрит в кладовку, стоит в проёме; проход занимает покупатель, тело или автомобиль: появление/выход удерживаются безопасно.
- Тревога, вызов полиции и возвращение; покупатель не мешает спасению продавца.
- Выгрузка/загрузка района не сокращает таймер, не создаёт двух продавцов и не сбрасывает кассу.
- Замеры в общей сцене до/после, включая двери и покупателей; CPU тесты не заменяют живую проверку.

## Фактическое состояние

В браузерном WIP подготовлен пилот только для print_shop / REBUILD-VISUAL-print_shop-001. CPU-проверки скрытого рождения, выхода, смерти, покупки и блокировок пройдены; последняя известная LIVE достигла printshop-active. Визуальная приёмка полного цикла и производительность общей сцены не подтверждены. Кладовки во всех зданиях и Godot runtime пока не реализованы.

Для переноса: Astra4 рассматривает геометрию/двери и схему якорей, Astra2 — жизненный цикл/экономику, Astra5 — регрессии. Общую интеграцию выполняет Координатор20 после проверки предложений. Этот документ не даёт статус PASS будущей реализации.
