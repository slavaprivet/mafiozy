## Adapter requirements derived from the source

1. Bind accepted session, actual actor reference/ID, life generation, source event and source authority mode before applying a reaction. Admission remains current; appearance replacement must not replay a previously consumed impact/death.
2. Use actual source-confirmed native contact/anchor when present. World point is metres; source row/column are not native point coordinates. Keep point, surface normal and travel direction separate. Do not infer contact/zone/side from damage, stamp, bodyPart or actor centre.
3. Keep source HP and physical presentation separate. Local ordinary NPC source decides medical survival before final death; player authenticated HP/armor remains combat_state.v1. No duplicate damage, manufactured death, new source IDs or client cover veto of authenticated combat.
4. No measured physical momentum J exists in the audited confirmation/HP chains. `.09` cell push, `_threeHitPower=damage/72`, and blast `visualSpeed:5` are source presentation values, not physical impulses. A native physics/calibration policy must state its own provenance; these values cannot establish measured force.
5. Source internal functions trust producer-created contexts. A new external native reader must validate finite/type-correct current data independently. `confirmed:true` does not itself prove context validity, contact, epoch or server authority.
6. Only source-owned definitive lifecycle/deathKey settles a corpse. Temporary stun/custody and zero HP before a medical survival decision must not permanently kill the rig. Missing source data preserves accepted lifecycle, rather than resurrecting or replaying it.
