# Выезд из парковочных мест — 19 сентября 2026

## Результат и граница ответственности

Новый `assets/maps/city_rebuild_v1/city_parking_origin.mjs` устраняет `parking_exit_unavailable` у четырёх мест больницы и двух мест `eastside_garden_walkup_v1-001`. Причина: место направлено внутрь двора, а начало проверенного выезда — наружу. Один непрерывный ход с одной передачей не может соединить эти противоположные позы в тесном дворе. Теперь используются физические манёвры с задним и передним ходом, затем сохранённый выезд на дорогу.

Геометрия парковок, разметка, игровые машины, ID и собственность не менялись. Владелец общей задачи подключает helper в `city_road_navigation.mjs` и read-only source query `parking-exit`; NPC follower принадлежит Artist17. Новый helper сам не двигает автомобили.

## Контракт

`createParkingOriginResolver({parking,isRoad,poseAllowed})` возвращает `resolve({from,profile,firstOnly=false})`, `diagnostics()`, `clear()`. Одноразовый эквивалент: `getParkingOrigins({from,parking,isRoad,poseAllowed,profile,firstOnly})`.

- `from={x,z,yaw}` в метрах, направление машины +Z. `profile.halfLength/halfWidth` тоже в метрах, проверяются на конечные положительные значения. Без профиля используется прежний CAR.
- Callback `poseAllowed(x,z,yaw,profile)` должен передать четвёртый аргумент в реальную проверку кузова. Проверка асфальтовой поддержки также использует именно этот профиль.
- Результат — существующий формат origins: `point`, `prefix`, `accessRouteId`, плюс `lotId`, `gearChanges`, `requiresLiveClearance`, `speedLimitKmh:5`. У каждой точки есть фактический body yaw и `gear`.
- `gearChanges` содержит `{pointIndex,from,to,requiresStop:true}`. В этой точке водитель должен остановиться перед сменой передачи. Это обязательное поведение потребителя; передача не разрешает скачок позиции/угла.
- Для admission достаточно `firstOnly:true`: проверить первый безопасный выезд без поиска дорожного графа и остальных направлений. Обычная маршрутизация оставляет оба направления.
- Обычные уже ориентированные позы сохраняют прямой C1 connector. Неподдерживаемый сложный произвольный старт остаётся blocked, не телепортируется на ближайшее место.

Используются шесть конечных шаблонов для существующих дворов на 2/4 места, составленные из дуг радиуса 4,3 м и прямых, с C1 присоединением к реальному началу выезда. Исследовательский hybrid search оставлен только в `outputs/roads_logical_20260912/probe_bay_manoeuvre.mjs`; в игре его нет. Конечные шаблоны проходят свежие полные проверки кузова/покрытия, а весь существующий driveway дополнительно проверяется с шагом ≤6,5 см и ≤0,9°. Кеш ограничен 128 геометриями и никогда не хранит результат clearance. Изменение препятствия учитывается следующим запросом. Возвращённые точки отделены от кеша и authored records.

## Дополнение: занятые соседние места

После LIVE-проверки Artist17 выявлена повторяемая блокировка: 20 из 57 готовых выездов пересекали геометрическое место соседней припаркованной машины. Это были первые места всех 17 двухместных дворов и места 0, 1 и 3 больницы. Повторное статическое перепланирование возвращало тот же путь, поэтому follower оставался на waypoint 0/1.

`city_parking_origin.mjs` теперь считает эти соседние места занятыми полными кузовами. В двухместных дворах и у внутреннего места больницы машина сдаёт назад по проверенной входной кривой. Для двух крайних мест больницы добавлены конечные многоточечные манёвры в свободной центральной части двора; runtime-поиска нет. Коллизии не ослаблены, соседние машины не перемещаются.

Новая проверка `test_city_parking_occupied_departures.mjs` подтверждает: compact_sedan получает выезд со всех **59/59** мест; во всех **20/20** ранее конфликтных случаях swept полный кузов с шагом ≤5 см / ≤0,5° не пересекает ни одно соседнее место. Профиль реальной машины теперь передаётся через `city_road_navigation.mjs` в worker, участвует в parking origin, destination sweep и заключительной проверке всего маршрута. До загрузки actor сохраняется прежний безопасный CAR fallback, чтобы ранний запрос не зависал.

Worker parity с реальным compact_sedan повторно пройдена для трёх полных городских маршрутов. Финальный опрос p50/p95 **0,061/0,122 мс**, максимум **0,680 мс**; смена поколения при добавлении/удалении статического препятствия блокирует старый результат и затем восстанавливает тот же маршрут. First-only admission после повторного использования кеша: p50/p95 **2,21/3,24 мс**, максимум **4,70 мс**; варианты после первого доказанного безопасного выезда больше не строятся. Отчёты: `outputs/city_lane_route_worker_20260919.json`, `outputs/roads_logical_20260912/parking_occupied_departures_audit.json`.

Большие civilian-модели по-прежнему могут получить честный `parking_exit_unavailable` в двух крайних местах больницы: существующий двор физически слишком тесен при трёх одновременно занятых соседних местах. Текущий доказанный source-сценарий использует compact_sedan. Выезд до дороги не доказывает доступность каждого назначения по directed graph. GPU-вкладки не открывались; новая сборка в LIVE ещё не перезагружалась, **производительность общей сцены не проверена**.
