# Exact NPC shot-contact CPU audit — 12 September 2026

Bounded follow-up requested by Artist16 root after its damage agent measured roughly 155 ms per accepted shot with 30 nearby actual GLB NPCs. That number is the parent's supplied benchmark result, not independently remeasured by this audit. No production ray/combat code was changed, and no GPU scene was opened.

`npc_contact_ray.mjs` prepares every visible actor within its existing generous ray-distance gate: updates world matrices (including the SkinnedMesh override), updates skeleton, recomputes skinned bounding sphere and optional box, then intersects all gathered surfaces. `world_walk_combat.step` performs an accepted camera aim query and a final physical muzzle query. The accepted-only admission improvement already avoids this work on rejected automatic-fire frames and is preserved.

Potential next optimization: a scope limited to one synchronous accepted shot, allowing the second query to reuse preparation for unchanged meshes. It must have an explicit per-shot identity and must invalidate on changed actor/root/ancestor transforms, bone matrices, bind matrices, skeleton/mesh identity, position/skin-index/skin-weight attributes and visibility. New unrelated queries/shots must start fresh. A moving NPC or prone transition between callbacks must be picked up immediately. Reusing only the first query's hit or reusing an actor list across the two different rays would be incorrect: the muzzle may see a different target or wall.

The existing 3-metre broad-phase centre is a permissive rejection test, not a proven exact bound for every supported animated pose. Sorting that heuristic and stopping before all potential nearer actors are tested could introduce false misses. Safe early termination requires conservative bounds which include the current displayed skinned surfaces, or reuse of exact preparation after validating the pose.

Required acceptance before production: real male/female GLBs standing/crouching/prone and arbitrary world transforms; zero-motion paired queries; altered pose/root/visibility/geometry between queries; a new unrelated shot; camera sees NPC but muzzle is blocked; different camera/muzzle nearest NPCs; clear miss; wall nearer/equal/behind. Compare ID, point, normal, zone and persistent surface anchor to uncached rays. Benchmark the same 30-actor scene before/after after warmup, separating matrix/skeleton/bounds preparation from triangle intersection. A controlled general-scene LIVE measurement is still required separately.

Root requested preserving the completed live damage fix if exact parity could not be established within approximately three minutes. This audit therefore leaves the working implementation unchanged rather than introducing an unverified skin cache.
