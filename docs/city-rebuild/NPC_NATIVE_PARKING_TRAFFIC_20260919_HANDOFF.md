Later continuation: [personal interdistrict trips and background routing](NPC_INTERDISTRICT_TRIPS_20260919_HANDOFF.md). Its asynchronous measurements supersede the synchronous lane-query limitation below for ordinary civilian trips; initial parking and overall LIVE acceptance remain separate.

Owner: Artist17 / traffic_finish. Source parked cars no longer use legacy parking coordinates when first created for native walk. Objects are queued before presentation, retaining original source identity, model and HP. `spawnParkedCar` and `_spawnParkingLotCars` mark only newly created ordinary parked cars. Already presented, occupied (including a retained dead occupant), owned, hijacked or active-trip cars are never repositioned.

Admission uses road owner's `parking-anchors`, exact bay reservations and actual loaded fleet collision profiles through `initial-vehicle-shape`. The host query returns half extents in source tiles (native metres / 4.1). Missing model/profile waits. A short physically clear exact connector now becomes a normal walking route and cancels its stale directed-search job. Cars stopped by another car/pedestrian keep their current route for twelve seconds before trying a replan, instead of redoing planning after 1.5 seconds of ordinary congestion.

## Follow-up: autonomous trip start outside the renderer — 19 September

Root review found that the scheduler asks for door coordinates before registering a trip, while the old logical access callback required an already boarded NPC. This made the previous far-driving check insufficient: a far trip could continue, but could not start.

The `query` phase now reads pure authored seat/door geometry from the admitted source catalog and the actual loaded fleet template. Each row carries a live viewer distance; geometry remains unavailable inside the visible handoff radius when the actual car is unloaded. A geometry query neither creates a trip nor grants boarding/driving permission. Pending source cars and unsupported/missing templates still have no usable anchors. `board`/`exit` transitions require the original living, unclaimed registry NPC and the matching source phase; `drive` still requires actual riding and drive phase. Source access requests carry their original NPC ID. Both civilian and ambient boarding pause before a physical step if their transition access is unavailable. Existing body-swept door paths remain authoritative.

`test_native_parking_lifecycle.mjs` now removes the actual car presentation before scheduling, rather than after boarding. Entirely far from the player, with no visible-car bootstrap, the same citizen completes approach → 12 boarding frames → 243.11m drive → 12 exit frames → 48.77m foot trip → actual hospital entry/browse/exit. PASS 2992 frames; CPU p50/p95 0.0745/0.1443ms (previous post-boarding unload scenario 0.069/0.133ms, separate runs; not a whole-scene benchmark). Maximum update 41.85ms still includes synchronous cold route work. The test explicitly proves that querying unassigned anchors creates no trip and grants neither boarding nor driving.
