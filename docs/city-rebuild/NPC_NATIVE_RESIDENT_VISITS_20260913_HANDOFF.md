# Native resident visits — Artist 17 scoped change

The previous visit removed a resident from `NPCS` after 420 ms at a legacy door, then reappeared at that door (or another available door). Native visits now use the already authored entry's `approachPoint`, `roomPoint`, `containsInterior`, `floorHeight`, `proximity` and `interact`. No building geometry was changed.

## Production scope

- `npc_resident_building_access.mjs`: `createNpcResidentBuildingAccess({getEntries,worldScale})`; existing traffic resolver dispatches `mode: 'resident-access'` to it. `list` returns stable `native:${instance.id}` doors; `open/status` reads actual animated door fraction. District detention entrances are excluded. Root owns import/dispatch in `walk_preview.mjs`.
- `world.html` resident functions: walk uses native doors while the native renderer is active. A stable destination survives a pending route, including a car-trip destination less than two tiles away. An explicitly selected trip destination is not substituted when temporarily blocked.
- `_residentNativeVisitTick` physically walks to a point inside the public entrance, pauses to look around, and walks back out. It uses the same full-body swept collision queries as walking. The resident remains in `NPCS`, with the same ID, HP, damage/death ownership and rendered actor. It does not use `RESIDENTS_INDOORS` for this cycle.
- A closed door waits for actual clearance. A blocked entry stops; after three seconds it physically returns along the approach. A death stops the visit immediately without moving/reviving the NPC. Existing replacement-resident spawning remains separate.
- An active visit cannot simultaneously be assigned a car or a new walking destination. Exit goes to the existing bench/routine scheduler; no nearby benches returns to a future shop task. Pending bench routing retains its selected bench rather than sleeping five seconds.
- Opt-in `html.dataset.npcResidentVisits`, once per second with `npcqa`, `npccombatqa` or `perfqa`, reports eligible residents, pending routes, physical visits and a status histogram.

## Limits and follow-up

### Pending-origin and fallback-walk continuation follow-up

The source generic movement branch could continue toward an obsolete `tr/tc` while `_civilianRouteTo` was waiting for the shared work queue. Waiting now sets that target to the current position (no position change) and clears temporary idle. `test_resident_pending_origin.mjs` reproduces the old drift from r=2.5 to r=5.0 with both frame slots occupied, then verifies a fixed origin and the same destination after admission.

Separately, `pickNpcWaypoint` discarded its whole breadth-first frontier each time the native 4 ms slice expired. Expensive predicates could prevent it from ever reaching its six-cell minimum. The existing cardinal frontier, nodes and queue index now survive slices in `_npcWanderSearch`, using the same global FIFO, maximum two admitted jobs per frame, 520-node bound and 4 ms window. Waiting preserves the original position. New directed/escape routes, route cancellation, death, panic, changed navigation callback or allowed surfaces invalidate the old walk search. A completed small reachable region can supply a walk shorter than six cells; blocked cells are not accepted to manufacture a route.

`node test_npc_wander_continuation.mjs` PASS: the previous discard behavior failed to produce a walk over 50 slices; two actual source FIFO owners completed in 113 frames with a controlled .45 ms predicate cost (1,038 checks total). It also covers a short courtyard, callback/surface changes, panic, death and external cancellation. This is a focused continuation/cost-control regression, not city geometry or FPS acceptance. Existing purposeful-plan, pending-origin and incident-reaction source regressions also pass. Opt-in once-per-second diagnostics now include at most eight jobs with age/frontier/expanded values and a separate `wanderPending` count.

Coordinator's latest reported live scene before this follow-up had 77 eligible residents, 32 directed pending and 17 physical visitors (7 entering, 1 leaving, 9 browsing). Pending alone therefore does not mean all actors are broken. No browser or additional GPU scene was opened; performance of the shared scene after this change has not been checked.

Later central LIVE at source time ~397 s showed four requests aged 125–207 s with zero frontier and 37 pending / 28 completed visits. Source audit found a remaining second admission gate specifically for benches: the first actor consumed the local one-visit slot even if the global FIFO refused it, preventing the actual FIFO head from requesting its turn. Native bench requests now use only the already existing global 2-job/4-ms admission, matching building visits; legacy local budgeting remains. A tiny actual-source reproducer keeps the old FIFO head at zero expansion for 12 frames and confirms expansion with the fix.

Cancelled civilian intents also left `_routeSearchPending` behind, including the `seek_shop` early return before any frontier existed. Directed requests now record their kind; cancelling a civilian intent or losing all eligible entry candidates removes only its civilian directed search and FIFO membership. An already superseding `help` request is preserved. `test_npc_route_wait_lifecycle.mjs` covers these cases; purposeful-plan, wander-continuation, pending-origin and incident-reaction source tests all remain PASS. This does not by itself identify the exact cause for every old LIVE ID. The next opt-in diagnostic includes request kind, plan phase/status, FIFO position, attempt/admission ages, retry/idle remaining and interruption for at most eight jobs once per second. No GPU run was performed.

The visit covers the public entrance area and looking around; it does not invent a purchase transaction or browse every room. Entry uses the direct authored entrance corridor and will safely return if furniture blocks it. Complex indoor destinations require authored, collision-checked paths. Original server/business IDs and individual boss logic are unchanged. Full actual car → exit → entrance → visit → leave validation belongs to the parent integration check.
