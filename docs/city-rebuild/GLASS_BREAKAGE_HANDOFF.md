## Подключение

```js
import {createGlassBreakage} from './glass_breakage.mjs';
const glass = createGlassBreakage(THREE, scene, {
  groundHeight: (x,z) => groundHeight(x,z), // world metres; fallback groundY=.035
  maxShards: 192, maxDecoratedPanels: 80, shardsPerHit: 28,
});
// После всех runtime замен геометрии/окон/создания входа.
glass.prepare(buildingVisual);
glass.prepare(car.object);
// weapon_effects сохраняет исходный THREE.Intersection.
onImpact: e => {
  glass.hit(e.hit, {
    direction: e.direction, // нормированное направление пули в world
    impulse: e.impulse, // относительная сила = damage; НЕ физические N*s
    weaponId: e.weaponId,
    // optional velocity: world Vector3 скорости автомобиля для наследования
  });
  // Авторитетную обработку HP/урона продолжает выполнять host.
};
glass.update(dt);
// Взрыв машины: до ручного скрытия прозрачных panes!
glass.shatterAll(car.object, {impulse:80, weaponId:'vehicle-explosion'});
glass.reset(car.object); // только машина; разбитые окна города остаются
glass.reset();           // весь registry
glass.dispose();         // ПЕРЕД dispose entry/residential/авто, восстанавливает источники
```

`prepare(root)` только регистрирует подходящие mesh, не меняет их. Можно вызвать
повторно после добавления новых объектов. `hit` лениво регистрирует незнакомый mesh.
`onHit` — alias `hit`. Результат `{broken,panelId,mesh,instanceId,triangles,shards,weaponId}`;
при отказе `{broken:false,reason}`. `stats()` отдаёт покрытие и активные лимиты.

При попадании передавать именно исходный `hit.object`, `hit.faceIndex`,
`hit.instanceId`, `hit.point`, `hit.face.normal`. Пересозданный объект только с point
не позволяет безопасно выбрать стекло. У InstancedMesh instanceId обязателен.

## Материалы, панели, сохранность

- Автодетектор: glass/glazing/windshield/windscreen в имени материала; либо в имени
  одиночного mesh; либо material.transmission > 0. Простая прозрачность сама по себе
  не означает стекло (частицы/лучи/маркеры не должны разбиваться).
- `mesh.userData.breakableGlass=true` или `material.userData.breakableGlass=true`
  включает явно; false имеет приоритет. Для mixed mesh помечать **материал**, иначе
  mesh-wide true означает, что все его материалы являются стеклом.
- В merged GLB выбирается material конкретного треугольника, затем связная панель
  по общим рёбрам. UV/normal seams виртуально свариваются по позиции для поиска,
  исходные атрибуты не меняются. Панели, касающиеся только углом, не объединяются.
- Удаляются только треугольники этой панели; индексы faceIndex стабильны, группы и
  фурнитура/рамы/соседние панели сохранены. Никакого hide всего curtain-wall mesh.
- У InstancedMesh заменяется только попавший экземпляр на отдельный mesh с его
  полной геометрией/материалами; исходный экземпляр получает нулевую матрицу.
  Стеклянная панель вычитается уже из replacement, соседние instance и рама целы.
  Матрица исходного InstancedMesh копируется; reset возвращает оригинальный buffer.
- Изменения только runtime. Материалы источников и shared GLB geometry не мутируют.
  InstancedMesh.dispose events освобождают старые GPU instance buffers при замене
  и reset; геометрия/материалы источников не dispose-ятся.

## Внешний вид и ограничения

Сеть радиальных, ветвящихся и нерегулярных кольцевых трещин проецируется лучом на
фактические треугольники панели. Через 85 мс панель выпадает: реальные треугольники
становятся вырожденными и больше не рисуются/не принимают лучи, у кромки остаётся
неровный стеклянный остаток. Он прикреплён к исходному mesh, поэтому движется с
автомобилем и створкой двери. Сама дверь и механизм E остаются у building_entry.

Осколки — объёмные треугольные призмы, один InstancedMesh, случайные размеры и
вращение, импульс пули, гравитация 9.81, отскок/трение от groundHeight, жизнь 2.2–3.4с.
Отделившиеся осколки живут в world, не приклеиваются к уже уехавшей машине. Скорость
машины наследуется при передаче settings.velocity. Лимиты сверху:512 осколков,
256 панелей с декоративной кромкой,64 осколка на попадание; defaults192/80/28.
Старая декоративная кромка вытесняется, но её разбитая панель не восстанавливается.

Ограничения для честной приёмки:

1. Это presentation, без изменения серверного урона/сохранений/собственности.
   Коллизии прохода через окна не открываются автоматически; дверь открывается E.
2. Топологически единая непрерывная поверхность стекла — одна панель. Если автор
   приварил разные оконные секции общими рёбрами одного материала, нужна правка
   геометрических границ панелей в asset, а не произвольная сетка разрушения.
3. Декоративная кромка использует выпуклый контур проекции панели. Сложные вогнутые
   и сильно изогнутые стёкла нуждаются в отдельной LIVE проверке. Удаление самой
   панели при этом всегда использует её реальные треугольники.
4. SkinnedMesh не регистрируется: нынешние автомобильные/строительные окна обычные
   Mesh/InstancedMesh. Физические полы для частиц задаёт host; крыши/кузов не входят
   в отдельную дорогую физику столкновений осколков.
5. Сохранять порядок lifecycle: apply entry/windows → prepare → hit/update →
   glass.dispose/reset → dispose входов/окон/авто. После reset объект можно разбить снова.

## Проверки

`node assets/maps/city_rebuild_v1/test_glass_breakage.mjs`

Синтетика PASS: два стекла + латунь внутри merged mesh; разные instanceId;
сохранение исходных index/instance buffers и sibling; повторное попадание в другое
стекло replacement; frame preservation; moving parent; bounded shards; decay;
mass shatter и reset/dispose.

Дополнительно PASS: reset(carRoot) сохраняет разбитые стёкла других объектов;
BoxGeometry с одним material рассматривается как цельная тонкая панель из12
треугольников (внутренние6groups в этом режиме renderer игнорирует); вырожденные
треугольники после runtime clipping не создают ложных glass panels.

Реальные pinned GLB всех19 размещённых типов загружены штатным GLTFLoader. Первый
прогон оригиналов PASS: стекло обнаружено в13 типах;6 частных домов используют
авторский WindowWarm и получают настоящее стекло через residential_windows.
Повторный полный прогон с residential_windows PASS для всех19 типов: этот runtime
слой проверен, WindowWarm не объявляется стеклом по предположению.
Node подставляет пустой Texture вместо DOM decoder, геометрия и материалы реальные.

LIVE сценарий координатору: одиночное окно жилого InstancedMesh (соседнее цело);
merged tower/pavilion (только одна панель); латунная дверная рама не ломается,
стекло двери ломается и после этого E продолжает вращать створку; боковое стекло
движущейся машины, осколки отстают; массовый взрыв, reset только машины, повторить.
