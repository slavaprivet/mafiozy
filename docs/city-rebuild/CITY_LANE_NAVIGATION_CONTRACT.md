# Дорожные маршруты и правила для walk

Владелец интеграции: «Автомобили — продолжение архитектора», задача `01a087f0-fda6-7e13-8baa-1bbd1c5cc26e`.

Это контракт сервиса маршрутов. Текущие `route`, `sweep`, `hospital`, `detention-access` и `driver` сохранены. Движением NPC владеет Художник 17; его CPU-подключение к этому сервису не является LIVE-приёмкой движения по всем полосам и светофорам.

## Запрос маршрута

Через существующий `registerWalkTrafficNavigationResolver`:

```js
{
  mode: 'lane-route',
  from: {r, c, angle},
  to: {r, c, id, buildingId, lotId},
  maxSnapDistance: 8
}
```

Все координаты этого интерфейса — исходные клетки мира, включая `points`, `snappedStart.point`, `snappedEnd.point`, их `connector.points` и `controls[].stopPoint`. Масштаб — 4.1 м/клетку. `angle` — исходный угол мира; внутри сервиса `yaw = PI/2 - angle`. Метры используются только для расстояний и `maxSnapDistance`.

Ответ: `ready`, `status: ready|blocked|pending`, `reason`, `points`, `distanceM`, `controls`, `destination`, `accessRouteIds`. Готовые точки содержат `r`, `c`, `angle`; парковочный манёвр также содержит `gear: reverse|forward`. Задний ход сохраняет направление кузова: нельзя автоматически разворачивать машину по касательной пути.

Цель-здание получает маршрут до проверенного въезда парковки и реальную длину оставшегося пешего пути `destination.walkingDistance`. Допускается другая парковка, только если подтверждён её пеший путь к тому же зданию. Явная цель `lotId` всегда сохраняется. Цель участка полиции ведёт к его настоящей служебной остановке. Для остальных зданий выбирается подходящая полоса у их публичного фасада, не точка внутри двери.

Карта игрока показывает этот путь при посадке в автомобиль. Пеший режим сохраняет обычную метку. При `blocked` прямой автомобильный маршрут не рисуется. Перестроение ограничено интервалом 1.5 с и заметным перемещением/поворотом, чтобы не запускать поиск каждый кадр.

## Правила движения

Контроли перечислены по ходу маршрута; вызывающий водитель выбирает следующий по пройденному расстоянию и тормозит до `stopPoint`. Сервис не двигает актёра и не определяет занятость перекрёстка за него.

```js
// Перекрёсток
{mode:'road-rules', approachId, turnId, time,
 occupiedTurnIds, occupiedCrosswalkIds}

// Отдельный переход между перекрёстками: передать control из lane-route
{mode:'road-rules', control, time, occupiedCrosswalkIds, occupiedEdgeIds}

// Въезд / выезд парковки
{mode:'road-rules', accessRouteId}
```

`time` — секунды одной общей игровой временной шкалы. Для светофора ответ учитывает фазу, несовместимые манёвры и занятые переходы. Для отдельной зебры `control.kind = pedestrian_crossing`, `crosswalkIds`, `edgeId`; это не искусственный перекрёсток. Проверенный разворот в конце дороги имеет `kind = road_end_turnaround`, ограничение 5 км/ч и учитывает `occupiedEdgeIds`. В обоих случаях обязательно сохранять полный `control.id` из ответа маршрута: правило сверяется с собственным индексом сервиса, неизвестный ID не даёт разрешение.

Правила въезда/выезда возвращают `requiresLiveClearance: true`, направление, ограничение скорости и точку принятия решения. Водитель обязан проверить реальный встречный поток и пешеходов; статический маршрут не выдаёт разрешение ехать сквозь них.

Пересечения зебр и переездов на физических парковочных хвостах также попадают в общий канонический `controls`. `requestedDistanceM` сохраняет положение требуемой остановки до начала локального участка. Wrapper находит её на полном маршруте, поэтому зебра сразу после поворота или начала въезда может требовать остановки ещё на предыдущем участке. Только если сам автомобиль уже начал путь после этой точки, возвращаются `distanceM:0` и `startInsideApproach:true`. Отрицательное значение не разрешает пересечь занятую зебру.

Дополнительный въезд может иметь внутренний `laneAnchor` с точными edge/progress/point/yaw подготовленного графа. Он проверяется по канонической геометрии, без увеличения допустимого snap-расстояния. Автомобиль, стоящий на парковке поперёк готового выезда, получает `parking_exit_unavailable`, если к выезду нельзя присоединиться физической кривой. Автоматический разворот на месте не создаётся.

Подготовка статических полных габаритов легкового автомобиля `CAR` и графа выполняется в environment worker после разметки, переходов и парковок. Там же заранее рассчитываются соединения с постоянными целями; основной поток восстанавливает индексы и кэш. Маршруты и хвосты подъездов сохраняют физические проверки, исходные ID и правостороннее движение. Габариты автобуса/грузовика и динамические препятствия водитель проверяет своим существующим `sweep`; стандартный статический граф не заменяет эту проверку.

## Проверка

`test_city_road_navigation.mjs` проверяет единицы всех полей, физический хвост въезда, препятствие между образцами пути, задний ход, альтернативную парковку, явную цель парковки, служебные остановки в трёх ориентациях, перенос данных перехода и сброс индекса при загрузке города. Полная карта проверяется отдельным actual-scene аудитом в `outputs/roads_logical_20260912/`. Итоговые количество маршрутов, LIVE и пределы производительности фиксируются в передаче этапа, а не в этом контракте.

Соединения с полосами, новые развороты и парковочные въезды отдельно проверяют радиус не менее 4.3 м и согласованность движения с направлением кузова. Старые кривые всех городских перекрёстков проверены на дорожное покрытие/полный кузов; глобальная проверка минимального радиуса каждого старого поворота и действующий кинематический follower NPC остаются отдельной работой.
