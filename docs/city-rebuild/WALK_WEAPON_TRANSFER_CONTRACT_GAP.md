# Перенос оружия между инвентарём и землёй: недостающий контракт

Проверка 2026-09-09. Локальная примерка `/walk` уже имеет G/E, сохранение магазина/резерва и TTL 300000 мс (`weapon_inventory.mjs`). Это локальный инвентарь с монотонным временем сессии; он не заменяет собственность основного мира.

В `world.html`, `mafiozi_bot.py` и `_preview_ws_server.py` нет существующих weapon drop/pickup запросов, подтверждений или списка оружия на земле. Есть отдельные банковские мешки и `gang_ammo_picked`; их нельзя использовать как передачу оружия.

Действующие точки: `loadInventoryItems()` читает `/inv/{uid}/list` с `items`, `ammo_state`, `combat_state`; `_selectProfileWeapon()` вызывает `/inv/{uid}/equip`. Серверные обработчики: `h_inv_equip` в `mafiozi_bot.py`, `inv_equip` в `_preview_ws_server.py`. Авторизация выстрела использует существующие классы оружия, а не локальные художественные идентификаторы.

Для работающих `dropWalkWeapon`, `pickupWalkWeapon`, `getWalkGroundWeapons` отсутствуют:

- Серверная атомарная операция снятия принадлежащего экземпляра/количества и создания ground ID, с подтверждением актуальных inventory/ammo/equipped state.
- Авторитетный снимок ground ID, исходного item ID, позиции/слоя, магазина/резерва, server created_at/expires_at. Срок 5 минут должен быть реализован сервером, сейчас серверного weapon TTL нет.
- Проверка дистанции/этажа, состояния игрока, дубликатов и одновременного подбора; атомарная передача получателю с удалением ground ID.
- Повторяемые request ID/receipts, восстановление после reconnect и единая семантика алиасов без потери исходных item ID.

Встроенный world gateway оставляет G/E для оружия недоступными до появления этих операций. Нельзя показывать успешный drop, менять локальную ownership map или удалять оружие через продажу. Самостоятельная `/walk` сохраняет готовую локальную механику. Bridge equip/fire/reload остаются отдельной действующей интеграцией.
