## Concrete bounded opportunities and unsafe shortcuts

1. **Keep one admitted factory/resource generation across editor operations.** `tools/godot/map_editor_assembly_candidate/catalog_factory.gd:51–68` already caches PackedScene per SHA; `spawn():103` instantiates independent nodes while real tests verify shared mesh/material resources. `configure():42` clears this cache. Procedural `configure():49–89` and transport `configure():97–115` reread/hash/decode buffers and construct all meshes/materials again. If the host reconstructs/reconfigures these on every editor enter/import-preview, retain a session generation for the exact admitted manifest + importer version + source byte snapshot instead. Move/delete/undo must only change object nodes/owned instance shadows, not resource generation. **Check host call frequency first**; code alone does not prove repeated configure occurs live. Hash-validation/invalidation must not be removed. New/changed source/importer or owner resource mutation requires a new generation, not a falsely warm cache.

2. **Load current GLBs lazily, then palette assets on demand.** Existing `cached_scene()` already enables this: first exact SHA load only. A host that preloads all196 can instead admit metadata and load the33 placed SHAs before first frame, leaving163 palette models available for first selection. Warm palette uses verified cache. This retains every object and full assets, unlike dropping content. Measure actual load requests/bytes before calling it a startup gain. Do not weaken resource hash validation or re-use a mutated PackedScene after admission.

3. **Do NOT deduplicate the apparent rail material duplicates.** All24 materials in duplicate groups (11–18/27–34 and19–26) are independently driven signal lamps. `transport_decor_factory.gd:463–475` writes each material's `emission_energy_multiplier` from the actual owner reply. Sharing the22 descriptor groups globally would link independent signals and change visuals/logic. Keep per-signal material instances; any proposed common immutable base must still fork dynamic state, with independent phase tests. This audit discovers no safe material-allocation reduction inside those44 from equal initial descriptors alone.

4. **Keep landmark mesh cache and warm owner-plan cache; do not rebuild them during movement.** Native `landmarks_resource_factory.gd:108–153` content-keys exact attribute/index/group/draw-range/primitive inputs and poisons changed resources. The separate accepted perf candidate already caches immutable source frames/local AABBs and computes the same per-part bounds. Previously measured CPU bridge preview1327/1575→314/400µs, island5387/6372→1469/1967µs; cold resource build essentially unchanged. These historical candidate CPU results are not new audit benchmarks or full-scene FPS. The117 material recipes remain uninstantiated/HOLD pending38 original textures/43 captures/PMREM. Do not merge them or install fallback colors to manufacture resource savings.

5. **Ground already shares small primitives/materials; preserve transactional chunk rebuilds.** `outputs/map_editor_ground/ground_document.gd:350–384` reuses host materials and one primitive mesh per kind; `ground_renderer.gd:127–136` carries cache references into staged changed chunks. New MultiMeshes are per changed chunk, not per cell. A whole-map recreation on every brush pointer would be a host integration regression: measure touched chunks and allocate only dirty plans while retaining rollback old resources. Never update shared BoxMesh/PlaneMesh size/material in place across chunks. Physical row-strip replacement and navigation callback ordering remain unchanged; resource reuse must not silently skip them.

6. **Keep road-paint edited meshes separate from immutable prototypes.** Procedural `_paint_commit():341–357` changes six owned vertices but replaces a complete batch ArrayMesh and retains meshBefore/meshAfter for undo. This is real per-edit allocation work. A bounded future candidate can coalesce pointer previews into one committed mesh or share immutable non-vertex CPU arrays, while creating an owned replacement vertex array/mesh; final vertices/UVs/normals/index/paint IDs/depth and full undo must match exactly. Do not mutate cached `_meshes` prototypes or do unverified raw GPU buffer writes. Any pooling must retain all resources referenced by undo/redo/checkpoints until release. Profile road batches first, since source sizes determine whether this matters.

7. **Reuse source textures and finish shaders, not mutable per-object material state.** Station adapter already keys prepared textures by source SHA + approved RGBA SHA + sampler/source key + mip algorithm, and caches material wrappers per original resource identity (`station_texture_adapter.gd:111–167`). `configure` currently clears caches; session-generation reuse can avoid repeat CPU mip construction after valid source admission. Original printshop `_mesh():340+` caches geometry+materials+color mode, `_material()` caches source index+colored role, Finish.shared_shader shares actual shader source. Preserve distinct uniform materials where source origin differs; source shader/material mutations invalidate owners. V2 shadow keeps all15 original batches; rebuilding280 instance nodes is not an optimization.

## Required measurable validation before implementation claims

- Instrument calls/counts: configure, SHA bytes read, PackedScene loads, ArrayMesh creations, Material creations, mesh/material resource IDs, MultiMesh uploads and dirty chunks. Compare cold first load, second editor open, palette reuse, import-preview cancel, move/delete/undo/redo and brush/paint stroke under the **same exact source/camera/population/settings**.
- Record CPU wall time p50/p95 over warmed identical operations, initial constructor time and retained memory/resource count with bounded cache/history. Cache-hit assertions alone are not an FPS claim. Track generation/owner changes and explicit invalidation scenarios.
- Verify every source submitted vertex/normal/UV/index/color and original scale/origin; collision world transforms/bodies, door state, physics strips and nav callbacks; record stable resource identity for unchanged prototypes and independent state for edited objects/signals. Headless MultiMesh getters are not storage proof; compare same-path CPU shadows and require coordinated real renderer parity separately.
- Test mutable alias attacks: modify one owned material/mesh/instance; other object unchanged or affected shared source generation correctly poisoned. Delete/undo must preserve referenced resources, not free shared textures. Failed owner/nav transaction must restore exact old resources and history. Cache keys include all sampler/transfer/primitive/shader/importer inputs, not model name or only color.
- Final LIVE validation through coordinator: same-view draw calls/triangles, frame-time p50/p95, visual/shadow/material/culling parity and interaction collisions. **Performance of the common game scene is not checked by this audit.** No resolution, textures, shadow quality, original LOD, lighting, object count, collision or gameplay changes are recommended.
