# Риски/регрессии в описанной схеме

## Смерть и состояние
- **Двойной death path**: принудительный `HP=0` на sever + «общий death path» через `CharacterPhysicsDriver31` могут сработать дважды (например, отсечение головы → HP=0 → death, плюс ragdoll-триггер по падению/коллизии). Нужен идемпотентный флаг `is_dead` и единая точка входа; иначе двойной ragdoll, двойное «Пал в бою», двойной звук/UI.
- **Причина смерти по последнему событию**: combat/fall определяется «последним», но при sever+падение порядок недетерминирован → возможна неверная причина («Разбился» вместо «Пал в бою»). Нужен приоритет: direct sever/death по combat важнее fall, либо таймстемп-окно.
- **Камера при смерти**: если HeroVitals умирает не через physics-драйвер (тестовый вызов), камера может не отъехать/не вернуться. Нет явного reset-хука камеры → залипание при respawn/restart.
- **Управление при смерти**: «выключается» через драйвер; если death path пришёл минуя драйвер (head sever с HP=0), input может остаться живым. Выключение ввода должно жить в едином `OnDeath`, не в драйвере.

## Монотонность и сброс
- **«Только убывает до reset»**: события травм, приходящие после reset (race со старой сценой/сигналом), могут «вернуть» урон или, наоборот, быть отброшены — состояние разъедется с визуалом. Нужен generation/token на reset.
- **Head sever = HP=0 принудительно**: если часть уже была 0 (severed), повторный sever → повторный death path без идемпотентности.
- **reset без ragdoll-restore**: драйвер вернул тело, а HUD/оружие/броня не пересобраны → «Здоров» но цвет части stale.

## HUD/приоритеты
- **Приоритет severed > critical**: часть может быть severed, но HP>0 (например, pre-set), либо HP=0 без severed → rule mislabel. Нужно явное «severed = флаг части», а не вывод из HP.
- **«Скрывает Здоров, но показывает кровотечение/горение»**: пересечение статусов (bleeding + injured) → какой иконке приоритет? Не описано, риск мигания/перекрытия.
- **Событийное обновление**: пропущенный сигнал (нет подписки на момент emit, смена сцены) → HUD залипает. Нужен один resync на `_ready`/reset, а не «раз в секунду».

## Броня/оружие
- **`equipped_changed` только на смену**: снятие/потеря брони при разрыве соединения (part severed во время экипировки) не триггерит сигнал → броня визуально висит на отсутствующей части. Нужна реакция на sever → переоценка брони.
- **«Накладывается только на целые части»**: при восстановлении части (reset) броня не вернётся без повторного emit.
- **Значок оружия из `walk_weapon_ui`**: переиспользование textures связывает два UI; при выбросе оружия (физический выброс 0.2с) значок обновится с задержкой до 0.2с → рассинхрон с инвентарём. И 0.2с-сверка «физического выброса вне инвентаря» может ложно триггерить на ragdoll/смерти (оружие выпадает физически) → «потеря» оружия при смерти.

## Тесты
- **«Монотонность цвета»**: тест не покроет reset-ветку (после reset цвет должен восстановиться). Нужен отдельный тест reset.
- **combat/fall death**: без теста резолва приоритета причины при sever+падение — регрессия не поймается.
- **Живые тесты без идемпотентности death** не отловят двойной ragdoll/camera.

## Сохранение реального состояния
- **Сохраняется ли `is_dead`, причина, severed-флаги частей, броня, оружие?** Если да — при загрузке нужно заново прогнать death path/ragdoll/камеру, иначе «мёртвый, но стоит».
- **Reset vs load**: если reset — это новый инстанс, а load восстанавливает HP частей напрямую, обходя монотонность/sever, можно получить HP>0 у severed головы. Нужна валидация при load: severed ⇒ HP=0 ⇒ death.
- **Сохранение «последней причины» без таймстемпа** при загрузке даст вечный «Разбился» на следующую смерть.

## Итоговые приоритеты фикса
1. Идемпотентный `is_dead` + единый `OnDeath(reason, priority)`; вход только через него.
2. Приоритет причины: direct sever > combat > fall, с таймстемпом.
3. Generation-token на reset, resync HUD/брони/оружия после reset/load.
4. Sever/restore частей → пересчёт брони и статуса.
5. Load-валидация инварианта: severed ⇒ HP=0 ⇒ dead; иначе «стоит после загрузки».
6. 0.2с-сверку оружия отключать в dead/ragdoll.
