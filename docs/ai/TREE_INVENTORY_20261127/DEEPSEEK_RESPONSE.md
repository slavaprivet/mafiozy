**Вердикт:** архитектура рабочая, но критичны три места: глобальная пауза, атомарность подбора и учёт лимита 32 тел через `queue_free`.

### Возможные регрессии
- `SceneTree.paused` глобально останавливает физику, таймеры, анимации, звук. `PROCESS_MODE_ALWAYS` ставить только на корень инвентаря, не на HUD/спавнер/ветер/игрока.
- `SceneTreeTimer` по умолчанию `process_always=true` — может спавнить overflow-поленья на паузе. Использовать `Timer` с `PAUSABLE` или `create_timer(..., false)`.
- GPU-ветер на `TIME` может продолжать двигаться при паузе. Если нужно замораживать — отдельный uniform, обновляемый pausable-нодой.
- Пауза может конфликтовать с другими меню: хранить предыдущее `paused`, не делать безусловный `paused = false` при закрытии.
- Курсор: сохранять и восстанавливать `Input.mouse_mode`, а не всегда ставить `CAPTURED`.
- После закрытия зажатая ЛКМ/B могут сразу дать атаку/повторное открытие. События B/Escape/крестика consume-ить, `is_echo()` игнорировать, на 1 кадр после закрытия подавить игровой ввод или использовать `just_pressed`.
- `queue_free()` отложенный: если уменьшать счётчик тел при подборе, можно на тот же кадр превысить 32. Слот освобождать в `tree_exited`, либо использовать безопасный пул.
- Low-poly дерево: детализацию добавлять в тот же mesh/material/surface одного MultiMesh. Новые материалы, отдельные ветки-ноды, alpha-cards на дерево — это рост draw calls/overdraw.

### Атомарность подбора
- E обрабатывать как `just_pressed`, не в `_process` по `is_action_pressed`, иначе можно «высосать» несколько поленьев.
- Выбрать одно ближайшее видимое полено, поставить ему `pickup_in_progress/reserved`, убрать из кандидатов/отключить коллизию.
- Без `await`: проверить, что `inventory.add(id, 1)` вернул успех. Только тогда `picked=true`, удалить из группы, `queue_free()`. Если add не удался — снять резерв, полено оставить.
- Нельзя `queue_free()` до успешного добавления. Каждое тело `wood_units=1`, добавление ровно 1.
- Учёт активных тел — по набору/словарю живых тел, декремент строго один раз в `tree_exited`/финализаторе. При подборе и при out-of-bounds cleanup не терять единицу: возвращать в overflow-очередь или inventory.
- Overflow-очередь должна быть pausable; при освобождении слота спавнить ровно одно тело, при неудаче спавна возвращать запись в очередь.

### Пауза и ввод
- Открытие: guard `if opened return`; корень инвентаря уже `ALWAYS`; `paused=true`; показать полноэкранный Control с `mouse_filter=STOP`; курсор видим; фокус на карточку/закрытие; событие открытия consume.
- Закрытие B/Escape/X: скрыть без ожидания анимации, восстановить предыдущие `paused` и `mouse_mode`, consume событие, подавить игровой ввод на следующий кадр.
- Игрок и оружие должны быть pausable, либо иметь центральный input-gate. Любые ALWAYS-автолоады не должны читать игровые действия при `paused`.

### Обязательные тесты
1. Открытие инвентаря: движение/атака не работают, курсор виден; B/Escape/X закрывают; восстанавливаются прежняя пауза и режим мыши; зажатая ЛКМ/B не дают атаку/двойной toggle.
2. Два меню: открытие инвентаря поверх другой паузы и закрытие не снимает чужую паузу.
3. UI: карточки из каталога, выбор мышью показывает описание, нет иконки — fallback, много предметов — скролл, resize/DPI.
4. Подбор: рядом два полена, E подбирает ровно ближайшее; +1; второе остаётся; повторный E не дублирует; полный инвентарь не удаляет полено; два E в одном кадре дают максимум 1.
5. Массовая рубка: N поленьев, в любой кадр включительно `active <= 32`; overflow = `N-32`; после освобождения слота спавнится ровно одно; после подбора всех — inventory = N, очередь пуста; пауза во время спавна не спавнит; out-of-bounds cleanup не теряет добычу.
6. Ускоренное падение: тайминги, отсутствие туннелирования/взрыва физики, корректный pause/resume.
7. Производительность: draw calls леса не выросли, один MultiMesh/material на тип дерева, FPS и vertex/overdraw в норме.
