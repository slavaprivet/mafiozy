## 2. «Руки вверх» — доказаны обе ветки

Стенд `proposals/qa58_surrender58/` (реальный ввод через вьюпорт: синтетическое движение мыши + ПКМ;
жителям не пишутся ни HP, ни маршрут, ни трансформ).

Прогон `runs/release03` — **прицел, удержание, опускание оружия, ни одного выстрела**:

```
DSH_SURRENDER58 stage=visible kind=visible_weapon
DSH_SURRENDER58 stage=enter   id=resident_1 from=ALERT at_s=0.72
DSH_SURRENDER58 stage=release id=resident_1 held_s=3.75
ok=true  aim_lease_ms_max=850.0  pose_max=223  pose_at_release=223
release_reason=aim_released58  phases_seen=[ALERT, SURRENDER58, IDLE]  shots_fired=0
```

То есть: лизинг прицела доходит до полных **850 мс**, поза держится **3.75 с** и **223 кадра** реально
записаны в скелет, при отпускании прицела срабатывает `aim_released58` и жизнь освобождается (`IDLE`).

Вместе с раундом 2 (вход из `ALERT`, `surrender_pose_frames=16`, стенд реакций **16/16**) обе ветки —
«прицел → руки вверх» и «убрал прицел → опустил» — подтверждены живьём. Выстрел по-прежнему прерывает
удержание (проверено стендом реакций: после прицела идут `near_shot`/`actual_hit` → `FLEE`/`PHONE`).

Тонкость, стоившая двух прогонов: ПКМ нельзя нажимать до того, как оружие «оживёт», иначе `_aiming`
остаётся `false` и `aimed_at` не рождается вовсе. Стенд теперь ждёт первое наблюдение `visible_weapon`
(как это делает штатный стенд реакций) и лишь затем жмёт ПКМ, повторяя нажатие идемпотентно.

## 3. Замеры FPS — чистая оконная пара и ночь

**Чистая оконная пара 1920×1080** (та же фиксированная камера, что в записанном протоколе qa31,
20 с прогрев + 90 с измерение, окно подтверждено `WINDOW31.json`):

| метрика | release57 (эталон) | общая 58 + стабилизация |
|---|---|---|
| кадров | 11 078 | 11 295 |
| средний FPS | 123.1 | **125.5** |
| p50 / p95 / p99 | 6.385 / 14.630 / 16.015 мс | 6.464 / **13.843** / **14.824** мс |
| максимум кадра | 28.26 мс | 31.58 мс |
| кадров сверх бюджета 60 FPS | 34 | **7 (−79 %)** |
| кадров > 33 мс | 0 | 0 |
| `physics_ms` p95 | 14 | **10** |

Гейты: `mean_fps ≥ 90 % эталона` ✓, `mean_fps ≥ 60` ✓, `p95 ≤ 16.667 мс` ✓.
Ограничение пары: она снята напрямую (штатный адаптер `run_perf58.py` больше не запускается, потому что
его предусловие требует указатель F5 на `residents57`, а указатель теперь открывает общую 58 — решение владельца).
Во время пары других процессов Godot не было.

**Оконная ночь** (те же часы 03:00 → 10:45, реальное окно, 20 с прогрев + 240 с измерение):
26 266 кадров, среднее **9.137 мс → 109.4 FPS**, p50 11.169, p95 16.530, p99 17.465,
**максимум кадра 22.178 мс**, кадров > 33 мс — **0**. Окно вышло даже крупнее 1080p (2778×1563),
то есть при большем числе пикселей. Оба ночных аудита снова `passed` (эпизодов 0, `failures=[]`).
Прежние 13 FPS из скриншота версии57 на этой сборке **не воспроизводятся**.

Headless 720 с для сравнения: 104 317 кадров, среднее 6.90 мс (≈145 FPS), p95 15.12, p99 16.24, max 69.73 мс.
Механизм «дрожания» измерен прямо: кадр **со** шагом города 13.97 мс против **1.90 мс** без него
(шаг идёт ровно 60 раз в секунду). Разовый всплеск 239 мс — привязка 10 жителей одним кадром на `city_ready`.

**Что включено в игровой набор по решению владельца** (33 аргумента вместо 32):
`--city-sim-one-per-frame=1` (стабилизация кадра: max 34.679 → 24.270 мс, кадров сверх бюджета 247 → 184,
кадров >33 мс 1 → 0, шаги симуляции не потеряны: 18 000 → 18 000) и `--city-surrender58=1`
(«руки вверх» при прицеле, обе ветки доказаны в разделе 2).
