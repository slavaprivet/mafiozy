# NPC58 — раунд 3: ночной гейт простоя и полное доказательство «руки вверх»

## 1. Ночной простой — авторитетный гейт ПРОЙДЕН

Новый вход `proposals/qa58_night58/entry_night_soak58.gd` сеет общие часы на **03:00** ДО создания сцены,
добавляет **штатный** observer-чейн проекта (`observer_soak58_v5` → v4 → v3 → v2 → mass → perf) и через
240 с переводит те же часы на **10:45**. Собранный `SOAK31.json` скармливается аудитам без изменений.

Прогон `proposals/qa58_night58/runs/night_soak01` (420 с наблюдения, 30 с прогрева, `stderr` 0):

| аудит | результат |
|---|---|
| `audit_spatial_liveness31.py` (окно 30 с, бокс 1.5 м) | **passed, эпизодов 0** |
| `audit_routine58.py` (необъяснимый простой > 10 с) | **passed**, `failures=[]`, `missing_evidence_samples=0` |
| максимальный необъяснимый простой по жителям | **1.0 … 3.0 с** при лимите 10 |
| события «выход → следующее действие» | **12** (включая переход 03:00 → 10:45) |

Итого гейт «никто не зависает» теперь закрыт и **днём** (720 с, раунд 2), и **ночью** (420 с с пробуждением).

## 2. «Руки вверх» — доказаны обе ветки

Стенд `proposals/qa58_surrender58/` (реальный ввод через вьюпорт: синтетическое движение мыши + ПКМ;
жителям не пишутся ни HP, ни маршрут, ни трансформ).

Прогон `runs/release03` — **прицел, удержание, опускание оружия, ни одного выстрела**:

```
DSH_SURRENDER58 stage=visible kind=visible_weapon
DSH_SURRENDER58 stage=enter   id=resident_1 from=ALERT at_s=0.72
DSH_SURRENDER58 stage=release id=resident_1 held_s=3.75
ok=true  aim_lease_ms_max=850.0  pose_max=223  pose_at_release=223
release_reason=aim_released58  phases_seen=[ALERT, SURRENDER58, IDLE]  shots_fired=0
```

То есть: лизинг прицела доходит до полных **850 мс**, поза держится **3.75 с** и **223 кадра** реально
записаны в скелет, при отпускании прицела срабатывает `aim_released58` и жизнь освобождается (`IDLE`).

Вместе с раундом 2 (вход из `ALERT`, `surrender_pose_frames=16`, стенд реакций **16/16**) обе ветки —
«прицел → руки вверх» и «убрал прицел → опустил» — подтверждены живьём. Выстрел по-прежнему прерывает
удержание (проверено стендом реакций: после прицела идут `near_shot`/`actual_hit` → `FLEE`/`PHONE`).

Тонкость, стоившая двух прогонов: ПКМ нельзя нажимать до того, как оружие «оживёт», иначе `_aiming`
остаётся `false` и `aimed_at` не рождается вовсе. Стенд теперь ждёт первое наблюдение `visible_weapon`
(как это делает штатный стенд реакций) и лишь затем жмёт ПКМ, повторяя нажатие идемпотентно.

## 3. Замеры FPS (для цели «стабильные просадки»)

| что | значение |
|---|---|
| оконный FPS в сборке 58 (скриншот владельца) | **131 FPS · p95 13.4 мс** |
| headless 720 с, 104 317 кадров | среднее **6.90 мс (≈145 FPS)**, p50 5.71, p95 15.12, p99 16.24, max 69.73 мс |
| кадр **со** шагом города (300 с A/B, 18 000 кадров) | **13.97 мс** |
| кадр **без** шага города (25 454 кадра) | **1.90 мс** |
| `--city-sim-one-per-frame=1` | max **34.679 → 24.270 мс**, кадров сверх бюджета 60 FPS **247 → 184**, кадров >33 мс **1 → 0**, `step_frames` без изменений (18 000) |

Вывод: средний FPS высокий, но картинка «дрожит» из-за 7-кратной разницы между кадрами со шагом города
и без него (шаг идёт ровно 60 раз в секунду). Известный разовый всплеск — привязка 10 жителей одним
кадром на `city_ready` (239 мс). Лечится включением `--city-sim-one-per-frame=1` (замерено, потерь шагов нет).
