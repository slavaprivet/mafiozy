## Контракт операций, необходимый до разблокировки

1. **Выбор и начало.** Рабочий владелец выдаёт receipt для точного ID, instance/generation, исходного SHA и всего набора зависимостей под настоящей паузой. Снимок включает неизменные resource identities, родительство, transform, видимость, layer/mask, shape, door state, occupants, route/nav generation и незавершённые jobs. Отсутствующий native объект или хотя бы один владелец — отказ до мутации. Права каталога и `locked` не меняются пользовательским флагом.
2. **Move/rotate.** Для банка единым delta преобразуются shell, обе двери, внутренние стены/пол/коллизии и source entry/vault anchors; пересчитываются footprint, дверной sweep, support и nav. Для изолятора вместе меняются shell, ramp, камера/ворота, stop/handoff/intake/release, полицейский подъезд и маршруты. Для железной дороги редактируется канонический путь/его ограничения, затем заново выводятся высоты, станции, переезды на пересечениях дорог, сигналы, train stop/dwell, blockers, полы и навигация. Простое перемещение visual root или отдельного proxy не обновляет эти данные. В исходном каталоге переезды прямо запрещены к ручному независимому сдвигу, сигналы привязаны к переездам, станции — к spline и остановке: самостоятельный move/rotate каждого такого ID остаётся **HOLD**, пока владелец не определит и не проверит правило перестройки родительского графа.
3. **RMB delete.** Тот же owner проверяет отсутствие людей в помещении/на платформе, открывающихся дверей, активной custody/convoy или train session и ожидающих path jobs. Удаление — атомарная операция владельцев: сохранить ID и исходную запись в истории как tombstone, скрыть/отсоединить точные визуальные и collision участников, убрать nav/route/stop/signal ссылки и дождаться подтверждения новой версии. Для alignment удаление затрагивает весь зависимый граф; для зависимого переезда/сигнала/станции отдельное удаление пока **HOLD** до явной source policy. Не `free()` исходные ресурсы ради undo.
4. **Undo/redo.** Восстанавливать/повторять единый checkpoint объекта и всех downstream владельцев, включая позиции и состояние дверей, occupants/custody, route/nav/collision versions и train phase. Не восстанавливать один GLB поверх более новой authority. Неуспешный rollback оставляет игру остановленной и требует ремонта владельца; ID никогда не переназначается.
5. **Save → fresh reload.** Записывать весь документ объектов и земли плюс 38 точных ID, source SHA/revision, исходные bank/detention records, железнодорожный spline и зависимые планы, tombstones и стабильные resource SHA. Не превращать 17 сигналов в 24 новых ID. Перед применением свежая сцена проверяет полное наличие ресурсов и owners, dry-run всех семейств, готовит rollback, совместно строит native geometry/collision и пересчитывает road/nav/NPC support/train; публикует одну согласованную версию только после подтверждения всех. `generatedPlans` хранит исходные записи, но runtime traffic/nav indexes должны пересобираться из закреплённых planners. Изолированные `test_atomic_import.gd` и V2 JSON циклы используют fixture callbacks; они не доказывают эту операцию в LIVE.

Следующая предметная приёмка: отдельно по каждому из трёх семейств получить настоящий owner capsule и негативные тесты отсутствующего/сменившегося владельца; затем проверить move/rotate/delete/undo/save→fresh reload всех 38 на реальных native participants при остановленных jobs и только потом на единственной LIVE-игре. До этого все 38 остаются видимыми в каталоге, но закрытыми для правок; CPU геометрия не меняет этот статус.
