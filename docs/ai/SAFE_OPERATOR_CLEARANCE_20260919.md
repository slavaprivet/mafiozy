# Сейф: створка не зажимает оператора — 19 сентября 2026

Исполнитель `safe_operator_clearance18`, узкий scope safe module/tests. CPU READY; **общая LIVE сцена не проверена**. Интеграция resolver принадлежит Координатору18.

## Подтверждённая причина

Существующая рабочая точка local `(0,0,1.34)` безопасна перед закрытым сейфом, но пересекается с раскрывающейся створкой. Радиус source-тела — `.18 * 4.1 = .738 м`; подход допускает `.08 м`. Физический тест воспроизводит исходное пересечение реального `getCollisionBodies()` во время открытия от 0 до -112 градусов.

Простой сдвиг на сторону против петли недостаточен: `x=+.65` всё ещё внутри промежуточной дуги. Полностью безопасные боковые точки заметно ухудшают контакт руки. На реальных male/female GLB с текущим `mercenary_pose` измерено расстояние palm→dial: исходная точка `.331/.294 м`, candidate `(.95,0,1.28)` — `.775/.733 м`. Уже существующий зазор исходной анимации остаётся отдельной визуальной проблемой; готовый физический контакт НЕ заявляется.

## Изменение

`interior_interactive_safe.mjs` принимает необязательный локальный `context.getOperatorPosition(memberId)` в `unlock`. Closure удаляется из context перед передачей авторитетному ledger. Разрешение/receipt и завершение работы не задерживаются. Створка остаётся закрытой, пока оператор пересекает весь безопасный объём её поворота. Штатный follow/rally выводит бойца из закрытого сейфа, затем сохраняется плавное раскрытие за `.85 с` и выпадение мешка. Если оператор возвращается до конца, движение створки приостанавливается. Уход на другой этаж или исчезновение оператора не блокируют её навсегда.

Защита — консервативный диск вокруг петли: `.80 м` включает видимую дверь, колесо и запорные планки; плюс `.738 м` тело и `.08 м` запас допуска. Геометрия, коллизии, рабочая позиция, источник денег и существующие анимации не изменены. `getState().waitingForOperator` показывает ожидание ухода. Без переданного resolver API совместим со старым поведением.

**Нужная интеграция root:** в `mercenary_walk.mjs` обработчик `onUnlock` добавить к существующему context `getOperatorPosition: id => host.getMember(id)?.position`. Это покроет QA и обычные интерьерные сейфы. Исполнитель не менял walk/source/core/route файлы.

**Ограничение:** если после завершения сам follow/rally не ведёт бойца за пределы дуги (например, игрок стоит у самого сейфа), дверь безопасно ждёт вместо насильственного открытия. Для гарантированного автоматического выхода во всех таких случаях нужен отдельный короткий source exit waypoint после completion. Этого исправления в данном scope нет. Проверить конкретный пользовательский LIVE сценарий ухода.
