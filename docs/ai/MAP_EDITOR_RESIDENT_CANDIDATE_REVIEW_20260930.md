## P1 — must close before any K integration

1. **Policy is not leased.** `build_candidate.mjs:152-159,183-185` captures only `policy.access_version()` and its object identity. `godot/mafiozi_walk/scripts/npc_visual/preview_resident_world_policy.gd:176-181` can dispose the policy without changing that version; `_owner_allowed()` also changes `dead_seen` without a version (`:117-121`). A direct `population.policy.dispose()` during pause can leave the population receipt apparently current and resume residents with a disposed admission policy. Give policy an owner-held lifecycle/state receipt or guarded mutation revision, compose it into begin/verify/end, and test disposal/state drift.

2. **Failed begin can strand live navigation.** `build_candidate.mjs:166-171` starts navigation first; if resident begin fails, it calls `navigation.end_editor_pause(nav_receipt)` and ignores failure while the tree is unpaused. Nav end may fail on an iteration/fault (`tools/godot/map_editor_nav_pause_candidate/pause_backend.gd:41-60`), leaving a paused backend under live gameplay. Add a verified rollback or terminal HOLD/disposal protocol and a forced rollback-failure test.

3. **End is not atomic across owners.** `build_candidate.mjs:193-205` ends navigation before testing the resident exact receipt. A changed resident body/rig can make `residents.end_editor_pause()` fail after nav already replayed held completions; re-pausing the tree does not re-lease nav. Verify *both* subreceipts before release, then provide a two-phase commit/failure contract. Test resident drift immediately before end and assert nav stays held on failure.

## P2 — proof and exactness gaps

- `build_candidate.mjs:43-76` records gait status but not gait object identity; it does not capture the resident host's `_navigation`, `_admit`, `_support` references or all body physics settings. Swapping a same-status gait or navigation reference, or changing `safe_margin`/motion settings, can preserve the visible snapshot yet change resumed behavior. Capture identity/owner-critical settings or explicitly refuse direct writes by capability/revision. An A→B→A change between verifications remains undetectable without a monotonic owner revision, as the candidate README notes.
- `test_actual_population_pause.gd:13-19` waits for navigation READY, but after timeout checks only population READY. The fixture may pass while nav is still BAKING/SYNCING. Assert nav READY before admission. Its `:40-42` no-mutation check compares the deliberately incomplete public resident `snapshot()`; compare the owner-held state/receipt instead. Add queued scene/body teardown, policy disposal, swapped resident dependency, forced begin rollback failure, and partial-end failure tests. The fixture's one direct rejected request proves only that guard, not full callback or source-authority coverage.
- The current candidate is deliberately limited to three local preview residents without live resident request IDs (`build_candidate.mjs:43-56`); the real queue owner exposes writable state (`godot/mafiozi_walk/scripts/navigation/path_job_queue.gd:6-29`). Full population, active routes, source agenda, impact/door callbacks and history-safe authority are not covered. A fresh narrow native fixture after source reconciliation is worth running for parse/API and three-body admission only.

Stop conditions: do not wire this to production K, call default residents READY, or unpause a mixed lease until source pins, policy ownership, rollback, and partial-end behavior are proven. Native fixture success would still not be LIVE/GPU/FPS or full-editor acceptance.
