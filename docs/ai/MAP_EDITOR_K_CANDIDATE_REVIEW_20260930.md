## Findings

1. **P1 — Cancellation can release the wrong or changed lease.** `pause_workspace.gd:144-153` ignores its `_request` argument, does not compare the current request ID, owner ID, or generation, and releases the gameplay clock and global `SceneTree.paused` state whenever `active` and the clock receipt are live. A delayed/direct cancellation from a prior request can release a newer K lease. The inherited Host also invokes cancellation when its enter verification fails; this callback does not recheck the player/body/door/water snapshot that caused the failure. Require exact request/current-owner matching, a verified rollback boundary, and retained paused fault on unknown partial state. Negative test: enter A, retire it, enter B, call cancel(A) and assert B remains paused with B receipt; independently mutate an owned state during enter verification and assert cancellation cannot unpause it.

2. **P1 — Global pause has no owner teardown path.** `pause_workspace.gd:118-119` pauses the entire SceneTree, but there is no `_exit_tree`/scene-replacement handler or explicit repair route. The probe manually resets `paused=false` after freeing each scene at `probe.gd:86-91`, which would hide a leaked global pause. Negative test: remove/reload the current scene while K is held and assert the old owner neither releases another scene nor leaves the new scene permanently paused. A failure after entry should remain recoverable through a current-owner path; ordinary Escape is only consumed while paused (`pause_workspace.gd:50-51`).

3. **P1 — Focus and held-input state can change without invalidating the lease.** Entry requires captured mouse and neutral physical inputs (`pause_workspace.gd:70-89`), but `_capture`/`_verify_pause` at `:91-100,122-126` omit `_free_mouse_look`, `_right_mouse_down`, `_jump_key_down`, `_jump_event_consumed`, and melee input/source state. Godot focus-out calls `preview_player.gd:694-702,723-727`, which releases controls, changes mouse capture, and cancels melee. That notification can occur while game processing is paused, yet the K snapshot can still compare equal. The held-input scan also checks a fixed keyboard/mouse list, while player movement/jump uses `Input` actions (`preview_player.gd:274-300,640-690`), which can be driven by other mappings or injected actions. Negative tests: focus out/in while paused and verify re-admission or explicit refusal; hold/release jump and E while paused; inject an action without a listed physical key and assert resume is refused or safely rearmed.

4. **P1 — “Idle melee” gate reads a nonexistent field.** `pause_workspace.gd:79-80` checks `_state.get("active", false)`. Actual `combat/melee_input.gd:160` returns `action`, `start`, `started`, `held`, and `sequence`, with no top-level `active`. A released but still active attack, source timer, or cooldown can enter even though the candidate claims idle-only admission. `combat/preview_melee.gd:110-135,158-159` uses the pending start/source state and `_cooldown`; none is captured in the pause snapshot. The derived gameplay clock is a useful active-time mechanism, but it does not establish idle admission or state integrity. Use the owner’s explicit action/source-timer/cooldown receipt, or deliberately admit active attack with full pause/resume proof. Negative tests: released LMB during contact/recovery, active cooldown, and pending source timer at K entry; verify state/pose/camera offsets and remaining active time after resume.

5. **P2 — Optional impact owner is absent from admission and snapshot.** `main.gd:43,506-518` can install `preview_character_impacts`; `character_physics/player_impact_host.gd:189-212` has its own physics advance and an external resolver. `pause_workspace.gd:70-100` checks only player pose/transport/melee, so a configured impact host is not accounted for. Active physical-impact pose is usually refused by the on-foot check, but the configured host and pending callback lifetime are not verified. Minimal default-preview rule: refuse K whenever that optional host is installed until it supplies a current hold/verify/resume receipt. Negative test: install an idle impact host, enqueue a source callback across K, and assert no event is admitted or lost without owner confirmation.

6. **P2 — Snapshot is not an exact transport/door/water receipt.** `pause_workspace.gd:91-100,114-115` stores `hash(_main._block)` and `hash(transport._session)` instead of exact source/session identity. The body snapshot omits native `_physics_tick`, `_control_sequence`, `_control_source_clock`, pedals, brake, contact state, vehicle/life metadata, collision shape/filter and freeze state (`vehicle_physics/vehicle_native_body.gd:19-40,95-109,218-225`). `preview_transport.gd:384-410` deliberately allows a moving empty car in `ON_FOOT`. The door snapshot has only fraction/target, not hinge transform/collider identity (`preview_printshop_interior.gd:158-189`). Water snapshot records phase but not host/material identity; the synthetic ground token carries an old water ID without rechecking the current one. A narrow K route can refuse moving vehicles and active door transitions until owner receipts exist. Negative tests: rolling ON_FOOT car; changed native control/source clock with same transform; door pivot/collider swap at equal fraction; water-host replacement at equal phase; exact source/session replacement at equal hash-shaped summary.

7. **P2 — Staging is not project-settings parity.** `stage.mjs` copies source scripts/assets and pins main/melee SHA, but creates a fresh minimal `project.godot` instead of copying the real project file. Real settings include main scene, 1280×720 display/stretch, renderer features, MSAA, and an editor plugin (`godot/mafiozi_walk/project.godot:11-35`). The stage uses a new user directory and Compatibility renderer. Its 54-check CPU probe (`probe.gd:26-91`) validates ordinary K entry/exit, duplicate press, held W, static body/player, water phase, and two refusal flags. It does not cover the negatives above. Keep the stage result described as isolated source-slice evidence, not real project or LIVE equivalence.

## Positive boundaries observed from source

- `pause_workspace.gd:50-68` has a K-release latch and consumes non-K events while active; the always-processing router is outside ordinary paused processing (`router_v2.gd:4-16`). The probe covers normal K release/repress and held W refusal.
- The candidate refuses residents/nav (`pause_workspace.gd:73`) because actual navigation can complete async bakes/queries (`navigation/preview_engine_navigation.gd:102-123,223-225`). This is a necessary limit; default `preview_residents_enabled` is false at `main.gd:36`.
- Water active time is offset on normal resume (`main_pause.gd:16-17`; `pause_workspace.gd:136-137`), avoiding the direct wall-clock jump from actual `main.gd:804-809` in the ordinary path. The probe does not establish focus/teardown/failure behavior or material identity.

**Conclusion:** HOLD for even default residents-off, on-foot pause-only acceptance until findings 1-4 have owner-verified fixes and focused negative tests. Findings 5-7 bound optional-owner and evidence claims. Full editor readiness remains entirely separate.
