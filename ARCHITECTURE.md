# Мафиози — карта систем и «грабли»

Краткий справочник, чтобы не вникать в монолиты заново. Подробная навигация —
в `world_index.txt` (клиент) и `bot_index.txt` (сервер). Регенерация индексов:
`python gen_index.py` и `python gen_index_bot.py`.

**Graphify** — визуальный сервис-карта проекта (один `graphify.html`): поиск по всем
функциям/WS-обработчикам клиента и сервера, **граф вызовов** (кто кого вызывает),
клик → точная строка на GitHub (клиент → `mafiozi-battle`, сервер → `mafiozy`), карта
систем, «грабли». Данные + граф ЗАПЕКАЮТСЯ из world.html / mafiozi_bot.py:
`python gen_graphify.py`. Заливка (сама перезапекает): `python github_upload_graphify.py`.
Живой URL: <https://slavaprivet.github.io/mafiozi-battle/graphify.html>

`gen_graphify.py` также пишет **`graphify.json`** (локальный, рядом с индексами) — вся
карта + граф вызовов одним машинно-читаемым файлом. Для навигации без грепов читать
его целиком: у каждого символа `calls[]` (кого зовёт) и `calledBy[]` (кто зовёт). Граф —
ЭВРИСТИКА по regex (тело функции до следующего объявления), связи приблизительные.

В graphify есть вкладка **🤖 Помощник** — чат на ключе пользователя (Groq/DeepSeek/Cerebras,
OpenAI-совместимый, ключ в localStorage). Токен-эффективен: на каждый вопрос сам находит
релевантные функции (категории по началу слова + граф) и шлёт модели ТОЛЬКО их код
(нарезка по строкам из raw GitHub) + «грабли». ~1–3K токенов/вопрос, а не весь монолит.
Советует/пишет код — правки пользователь вносит сам (страница не редактирует файлы).

**`quick.py`** — то же самое в терминале (дешёвый исполнитель ЛЁГКИХ задач мимо Opus):
`python quick.py "вопрос"` (ответ), `python quick.py -e "задача" --yes` (применить правку:
блок FILE/FIND/REPLACE → бэкап → проверка синтаксиса → откат если сломал). Контекст режет из
ЛОКАЛЬНЫХ world.html/mafiozi_bot.py по graphify.json. Ключ: `python quick.py --save-key groq КЛЮЧ`
(в `ai_config.json`, gitignore) или env. Двойной клик: `БЫСТРО.bat`. Политика: сложное — на Opus, лёгкое — сюда.

## Архитектура

```
Telegram WebApp
   │
   ├─ hub.html ──(open)──► world.html   ← КЛИЕНТ игры (изо-мир, ~30k строк)
   │                          │  WebSocket
   │                          ▼
   └────────────────►  mafiozi_bot.py   ← СЕРВЕР (Python, Railway, ~19k строк)
                              (авторитет: hp/смерть/тюрьма/wanted/worldCops/деньги/снапшоты)
```

- **world.html** — рендер, ввод, локальные NPC (cityCops, жители, охрана банка),
  клиентская физика. Шлёт серверу `input/shoot/bank_rob_*/citycop_arrest/open_fire`.
- **mafiozi_bot.py** — истина по hp/смерти/тюрьме/деньгам. Шлёт клиенту `snapshot`
  (`d.me.hp/dead/jail_in/...`), `cop_shot`, `cop_hit` и пр.
- Заливка клиента: `python github_upload_world.py` (из воркtри — сам берёт локальный
  world.html, проверяет синтаксис node'ом, заливает на Pages). Сервер деплоится отдельно.

## Системы координат (ГЛАВНАЯ ловушка)

- **Мировые координаты**: `player.r, player.c` в тайлах карты (0..MAP_ROWS/COLS).
- **Банк-интерьер**: пока `_bankInt` активен, `player.r/c` — ЛОКАЛЬНЫЕ координаты
  комнаты (0..W, 0..H), НЕ мировые. При входе мировая позиция сохраняется в
  `_bankInt.savedR/savedC`.
- ⚠️ **Нельзя слать серверу `player.r/c` пока в банке** — он решит что игрок
  телепортнулся в угол карты. `sendInput()` шлёт `savedC/savedR` пока `_bankInt`.
- ⚠️ Любая мировая логика (паника NPC, witness-chain, копы-преследование) по
  `player.r/c` в банке БЕССМЫСЛЕННА — гейтить через `!_bankInt`.

## Авторитет сервера vs локальные системы

- Снапшот сервера **перетирает** hp/dead/jail_in каждый тик.
- Локальный урон (охрана банка, cityCops) — через `_hurtLocal(dmg, by)`:
  ставит `myDead + _localDeath`, респаун ведём сами в больнице (сервер не знает).
- `_localHpHurtAt` — пока свежий (2.5с), снапшот НЕ поднимает hp обратно.
- **`_bankShield()`** = `_bankInt || (6с после выхода)`. Пока активен — ВСЕ серверные
  воздействия (hp/dead/jail_in/cop_shot) игнорируются. Закрывает баг «сервер убил
  worldCop'ами у входа, снап dead=true прилетел сразу после выхода».

## Протокол WS (основное)

Клиент → сервер: `input`(x,y,ang,w), `shoot`, `open_fire`, `citycop_arrest`,
`bank_rob_start/announce/bag_loaded/deliver`, `bank_bag_drop`, `npc_melee_shoot`,
`capture_try`, `chat`. (полный список — `bot_index.txt` → WS-обработчики)

Сервер → клиент: `snapshot`(d.me{hp,dead,jail_in,wanted,cash,...}, cops, others,
territories, event), `cop_shot`(killed,jailed,target_uid), `cop_hit`,
`citycop_arrest_reply`, `world_heal_reply`. (в world.html — поиск `kind === '...'`)

## Грабли (по горьким фиксам)

1. **Координаты банка утекают серверу** → ложная смерть/тюрьма. Гейт `!_bankInt`/`_bankShield()`.
2. **Серверный снапшот воскрешает/убивает** — при локальной смерти держим `_localDeath`.
3. **Тюрьма**: кламп движения в квадрат двора ±3 от `JAIL_CENTER` (76,76); центр —
   здание (раньше блокировал проход). Решётка рисуется R=4.3, не `JAIL_RADIUS_TILES=7`.
4. **render() в банке** уходит в `drawBankInteriorScene()` и НЕ доходит до мировых
   `drawBullets()` — боевые эффекты надо звать внутри банковского рендера.
5. **`npc_melee_shoot` от охраны банка серверу** = server-side arrest. Урон банка —
   только локальный `_hurtLocal`.
6. **Заливка**: `github_upload_world.py` берёт world.html рядом с собой (или argv[1]).
   `.token` — только в основном `Desktop\Мафиози`, скрипт ищет его вверх по дереву.

## Наёмники игрока (`_myGang`) — НЕ ПУТАТЬ с враждебными бандами

Два разных «банда» в проекте:
- **`aggroZones`/`gangNests`/`gang_dmg`/`updateGangAggression`** — враждебные уличные
  банды, атакуют игрока. Server-authoritative (боты внутри `aggroZones[id].bots`).
- **`_myGang`** — личный наёмный отряд игрока (найм у бандитов за $100, ранг 5+,
  макс. `GANG_MAX=5`). Полностью клиентский, не онлайн-игроки. Ключевые функции:
  `_hireGangMember()`, `_updateGang(dt)`, `_findGangCompanionTarget(m)`,
  `_gangTargetPos()`, `_saveGang()/_loadGang()` (persist в localStorage).

`_updateGang(dt)` вызывается ОДИН раз за кадр из общего тика — раньше был
дублирующий вызов внутри интерьера обычного здания (двойной урон/скорость),
и НЕ вызывался вовсе в ветке банка (наёмники физически замирали, пока игрок
внутри банка) — оба фикса 05.07.2026, см. git log.

Приоритет боевой цели наёмника (`_findGangCompanionTarget`): NPC банка (если
внутри) → городской коп, который УЖЕ преследует (`cop._pursuing`) → бандит
из `aggroZones` → банда-машина конвоя → коп мира, только если `myWanted>0`.

⚠️ **`hitCityCop()` шлёт `open_fire` от игрока при КАЖДОМ попадании** (поднимает
розыск). Наёмники гейтятся по `_pursuing`/`myWanted>0`, чтобы не ПРОВОцировать
розыск сами, а только подключаться к уже идущей погоне.

## Квартиры в обычных зданиях (`_myApartments`) — добавлено 06.07.2026

Покупка личного жилья в НЕтематических зданиях (`MAP[r][c]===1`, не POI/банк/
бизнес/участок/больница/спортзал/биржа/чёрный рынок — те уже исключены теми
же проверками, что и вход `enterBuildingInterior`). Не путать с `property_owned`
(старая система магазина/статусов) и `myBusinesses` (POI-бизнесы с доходом).

⚠️ **Ключ квартиры — координаты ГОРОДСКОГО БЛОКА, не тайла входа.** Здание —
весь внутренний квадрат 4×4 одного блока (`buildMap`: r/c % BLOCK ∈ {5..8}),
а игрок может подойти к разным тайлам фасада с разных сторон
(`nearBldR/nearBldC` в `updateGtaInteractions` меняется от угла подхода).
`_aptBlockKey(r,c) = floor(r/BLOCK)+','+floor(c/BLOCK)` — используется
ВЕЗДЕ (покупка/проверка владения/бейдж/цена), иначе один дом с разных
углов был бы то куплен, то свободен.

Сервер: `apartments_owned` (SQLite), хендлеры `/apartment/{uid}/state|buy|upgrade`
в `mafiozi_bot.py` рядом с `/biz/*`. Апгрейды (сейф/оружейный шкаф/гараж/
камеры/ремонт) — 3 уровня, цена растёт ×1.75 за уровень.

## Грабли рендера (05.07.2026)

7. **`items.forEach(i => i.draw())` без try/catch** во всех 9 местах рендера
   (главный `render()` + 8 интерьерных сцен) — один объект с NaN-координатами
   рушил исключением весь `forEach`, и всё что шло ПОСЛЕ него по глубине
   (включая игрока/здания) не рисовалось в этом кадре → «мерцает, пропадает
   персонаж». Теперь каждый `draw()`/`fn()` обёрнут индивидуально.
8. **Сравнение с NaN в поиске «ближайшего»** (`if (d > best) continue;`) —
   NaN всегда даёт `false` с обеих сторон, поэтому один битый объект (машина
   без корректных r/c) НАВСЕГДА залипал как «ближайший», независимо от
   реальной позиции игрока. Смотреть на направление сравнения при добавлении
   новых `nearestX`-паттернов.
9. Такая NaN-машина типично появляется, когда новый объект в `CARS` не
   распознаётся `updateCars()` как `parked` (проверяется ИМЕННО поле
   `car.parked`, без подчёркивания) — тогда он проваливается в обычную
   логику движения трафика без путевых точек.
