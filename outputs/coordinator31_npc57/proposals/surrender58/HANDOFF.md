# surrender58 — «руки вверх», когда игрок целится в жителя (перенос из web walk)

Статус: **НЕ ПРИНЯТО**. Код сохранён как патч, из сборки вынут, дерево возвращено к пинам stage58_07.

## Что это

Порт поведения из web-walk: пока игрок **целится** в безоружного гражданского (ПКМ + оружие в руках),
житель **останавливается, поворачивается к угрозе и поднимает обе руки**; убираешь прицел — руки
опускаются через затухание позы, и жизнь возвращается к обычным делам.

Реализовано за флагом `--city-surrender58=1` (**по умолчанию выключен**, дефолт не меняется):

| файл | правка |
|---|---|
| `scripts/npc_ambient/ambient_pose28.gd` | новый threat-kind `surrender58` список `THREAT_KINDS`, ветка в `compose()` (обе руки выше головы, дыхание 2.05 Гц, дрожь 6.4 Гц, покачивание 0.7 Гц — как `sampleNpcSurrenderGesture` в web) |
| `scripts/city/runtime/npc_threat_life30.gd` | фаза `SURRENDER58` + лизинг `AIM_LEASE58=0.85 с`, публикация меты `npc_ambient28` (kind `surrender58`) в текущем физкадре, `sample_current`, сброс в `cancel()`, наблюдаемые поля в `snapshot()` (`surrender58`, `aim_until`, `aim_lease_ms`) |

Окно позы 8.0 с фиксировано, потому что `ambient_pose28.sample()` принимает `duration_s` только в [4,8];
`elapsed_s` держится чуть ниже начала затухания, пока прицел свежий, а на отпускании доигрывает затухание 0.35 с.

## Почему не принято (измеренный факт)

Живой прогон стенда `proposals/attention31_resume/regression/threat/entry56.gd`
(оконный, 1280x720, полный набор флагов 57 + `--city-surrender58=1`, `--city-threat30=1 --city-physical-dispatch30=1`):

* прогон чистый: `stderr` 0 байт, отчёт `CITY_THREAT56.json` записан;
* в отчёте **70** записей с полями `surrender58` / `aim_lease_ms`, то есть новый код исполнялся;
* но **фаз `SURRENDER58` — 0**. В снимках видны `(ALERT, aimed_at)` и `(FLEE, aimed_at)`:
  фазу выбирает `_release_service()`, а `_event.kind` на тот момент был ещё `visible_weapon`/`near_shot`,
  и к моменту, когда `_event` становился `aimed_at`, фаза уже была выставлена в ALERT/FLEE.
  Повторный выбор фазы при усилении события (`acquire`) для `SURRENDER58` не предусмотрен — это и есть дефект.
* стенд `attention31` при этом даёт `passed=false` с `reason=actual_nonfatal_hit_not_completed` — это
  отдельная, ранее известная незакрытая проверка (метка `surrender` в хитовой цепочке мертва,
  `npc_local_preview_hit_owner.gd:390` возвращает false), к этому патчу отношения не имеет.

## Следующий шаг (в порядке)

1. Выбирать `SURRENDER58` не только в хвосте `_release_service()`, но и в `acquire()`: если пришёл
   `aimed_at`, а фаза `ALERT`/`FLEE`/`RECOVER` ещё не начала физический отход (`_driver.status` не `walking`),
   переводить в `SURRENDER58` без повторного релиза сервисов.
2. Писать в снимок/лог `DSH_SURRENDER58` строку (фаза, `aim_lease_ms`, кадр публикации меты), чтобы
   доказательство читалось из `stdout`, а не только из `snapshot()`.
3. Перепроверить на том же стенде: ожидаем `SURRENDER58` в фазах, `pose_frames` растёт,
   и после снятия прицела — `cancel(reason=aim_released58)`.
4. Замер визуально: кадр с поднятыми руками (стенд умеет сохранять PNG).
5. Отдельный прогон **без** флага — доказательство, что дефолт не изменился (ожидается пофазно идентичный отчёт).
