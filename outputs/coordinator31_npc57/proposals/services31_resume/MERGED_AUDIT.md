# Read-only аудит merged01 — 15 октября 2026

Объект: шесть файлов `INTEGRATION_merged01.json` в общей `game57`.
Их фактические SHA256 совпали со всеми шестью candidate SHA integration manifest.
Исходники не изменялись. Дополнительные движки не запускались.

Вывод для текущего объёма **10 жителей + 12 сотрудников**: конкретного
блокирующего дефекта в прочитанном объединённом коде не найдено. Это scoped
code review, не замена продолжающейся игровой/длительной/FPS приёмки.

Проверены четыре passage-файла, два attention/threat-файла, контракт живого
индекса `preview_resident_host.active_records30`, staff actor/host и registry.

- Вход в проход: native пары и локальное избегание используют один текущий
  набор тел. Планировщик исключает только живых участников целевой области.
  Повороты attention/threat не владеют collision masks и не меняют эти наборы.
- Выход из области: на следующем физическом обновлении пара исчезает из wanted
  и удаляются только исключения, добавленные этим helper. Восстановление
  столкновений у края области намеренное. Полная совместная эвакуация двух
  перекрывающихся тел за границу не доказана отдельной fixture; normal
  service complete → roam в merged soak должен подтвердить отсутствие очереди
  зависаний у края. На просмотренном промежуточном логе merged600_01 уже были
  четыре законченных shop цикла и последующие roam_arrived, highlights=[];
  это только промежуточное наблюдение, не итог soak.
- Стены, пол, закрытая дверь, player и debris: native исключения всегда между
  известными living CharacterBody3D, глобальные слои/маски не меняются.
  Capsule/floor query сохраняют collision mask; debris512 отдельно проверяется
  перед реальным движением. Peer-free ray-hit проверен native fixture, код
  оружейных запросов не затронут.
- Сотрудники: actual `_rows[*].actor` и collision_layer=1 совпадают с collector.
  PlacementProbe имеет layer0 и не получает исключений. Staff у кассы обычно
  стоит глубже 3,3-метровой области, поэтому касса и сотрудник остаются обычными
  препятствиями вне прохода; это не отключение всей внутренней коллизии.
- Смерть/новая жизнь: живость проверяется до типизации freed-объекта. Layer512,
  queued_free и недействительные body пропускаются. Ключ пары содержит native
  instance IDs, поэтому новая жизнь не наследует прежние исключения. Same-frame
  query повторно проверяет `_live(peer)`; old pair удаляется на следующем refresh.
  Native physics_candidate06 подтвердил death/respawn/free/cleanup.
- Ограниченность: обновление один раз на physics frame; зоны пересобираются
  максимум раз в секунду либо при смене количества entries. Сохраняются только
  текущие actors/members/pairs. При текущих 22 телах теоретический максимум
  231 пары, при шести нативно проверены 15 пар и полная очистка. Пройденные
  fixture не дают права на вывод о городском FPS.
- Attention/threat сохраняют health/combat/exact-life приоритеты, а неуспешный
  attention_pause только поворачивает body и возвращает управление service
  retry. RECOVER retry запускается только после двух секунд и свежего
  authenticated observation; пределы route attempt/work остаются у драйвера.

Конкретное ограничение перед будущим масштабированием: MAX_PER_ZONE=32.
33-е тело не получает `body_zone` и симметричную native пару, но
`query_exclusions()` для него по-прежнему может исключить уже принятых 32 peer
на цели в проходе. Это означает несовпадение planner/native admission при
переполнении. Для текущих 10+12 оно недостижимо, поэтому не блокирует эту партию.
Перед партиями, где у одного входа могут быть более 32 живых тел, нужно либо
согласовать исключения с membership, либо отдельно реализовать и проверить
overflow поведение. Увеличивать cap без измерения стоимости пар нельзя.

В актуальной приёмке нужны: завершение merged600_01, четыре настоящих service
циклов с выходом и roam, актуальная weapon/reaction проверка, чистый FPS через
scheduler после освобождения пользовательского окна. Никакие из этих проверок
этот read-only аудит не объявляет завершёнными.
