## Binding blockers / required corrections

1. **P1: lifecycle callback may invalidate the capability during the last validation, then force still commits.** `_live` lines44–51 checks `_disposed/_configured`, host status and binding BEFORE calling external `record.current.call(...)`, then returns the callback bool without rechecking anything. `_admit` line125 uses this as its final lifecycle check; `dispose()` does not refuse busy and clears global capability state. A current callback that calls port.dispose() and returns true leaves the local `body` valid/unfrozen; line130 can still apply_impulse after disposal. Similar callback replacement can change host mode/filters after status was sampled. Reentry guard covers nested admit only, not disposal or owner lifecycle mutation. After any external callback, revalidate port configured/notdisposed, same captured epoch/player identity, current host mode/binding and exact owned segment/filter state before commit. Add a callback-dispose/rebind/retire test which returns true and proves zero impulse/accepted-count, not just ordinary false-capability rejection.

2. **P1: epoch1 is reused by every fresh port, so rebind does not uniquely identify capability.** `_epoch:=1` line11 and empty `_seen/last_ms` on a new instance permit a same-frame request from a disposed prior binding to present the new binding's epoch1. Geometry/body-velocity checks may happen to reject some requests, but they are not a replacement for capability identity. Generate a per-instance unique epoch (e.g. actual Object instance ID, or root-supplied monotonic owner generation) and change it on every binding retirement. Tests should replay the old request against a newly configured port in the same physics frame and require frame_or_epoch rejection before force. Keep sampler's epoch contract unchanged: it already forwards returned integer epoch.

3. **P2: readiness scans actors and the actual rig subtree each moving frame.** `player_final_dead_contact_ready` lines52–57 iterates up to128 records, allocates host status/binding dictionaries, deep-copies binding for each `_live`, then callback `physical_life_current` performs `record.motion.find_children('*','Skeleton3D')` at preview_resident_host545. Native test wires this exact callback, so this is a concrete hidden scan, not hypothetical. `_last_attempt_ms` in sampler54 only throttles after a proposal; absent contacts keep calling ready each physics frame. Bound availability should be O(1): use owner-published active final-dead capability count/generation updated at lifecycle edges, or return only configured capability availability and leave exact target validation to O(1) RID-selected admit (with explicit extra empty-world query cost). Do not cache authority without invalidation. Admit's `owned_bodies()` additionally builds/scans16 entries; this is bounded and less urgent, but should be counted. Profile before claiming no-scan or cheap-empty-world behavior.

4. **P2: current callback proves actor/rig identity, not that registered physical host is still the source's active host.** The test callback calls physical_life_current(binding), which checks session/source/life/rig but does not compare `_ragdolls[source_id]` with the registered host/lease or revalidate source HP0/dead. Old host status alone could remain ACTIVE/final_dead if a same-life physical capability is replaced incorrectly. Registration needs an owner public current-physical-capability check including exact host/lease identity and terminal source death, not merely a generic walking-body binding. This is a stale-host gap to close before allowing arbitrary128-record registration; it is not a claim that current normal retirement already leaks a host.

5. **P1/P2 producer proof gap: last move is not necessarily this physics frame's move.** Port validates r.physics_frame against Engine current frame and reads CharacterBody3D.get_position_delta, but that returns the last move_and_slide displacement without a frame stamp. Source player `_pose_epoch` advances only when pose authority changes (preview_player530), not every walking step. A copied request with updated clock/frame/event fields can therefore present an old completed movement before this frame's player movement, or when movement processing is paused. A unique root-owned completed-movement frame/serial/start/end proof should be consumed once; do not treat pose_epoch as that proof. Alternative is an explicitly trusted private producer admission capability, but that must be stated rather than claiming independent current-move authentication. Negative test: walk in previous frame, perform NO move_and_slide in current frame, submit copied request with refreshed frame/time; require rejection without new query/force. This needs a coordinated root sampler contract change, not an author-only hidden field. Godot describes get_position_delta as the last movement: [CharacterBody3D documentation](https://docs.godotengine.org/en/stable/classes/class_characterbody3d.html).

## Energy / response acceptance still missing

- The formula bounds each selected segment's predicted speed/angular speed and added kinetic energy per event. It does NOT bound cumulative whole-corpse energy/momentum over repeated impulses across different limbs. At maximum allowed3Ns/80ms, the upper impulse-rate bound is37.5Ns/sec per corpse; max point energy2J/event allows25J/sec before dissipation. Current test options are lower1Ns/160ms, but all valid options require measured support. Keep those values labelled proposal limits.
- `test_three_actual_corpses.gd` breaks toward walking after its FIRST successful admission, then watches120ticks. That is useful single-contact response, not a sustained-burst/cooldown/multi-limb admission proof. Add several seconds of continued normal walking/overlap at the admitted cooldown, two independent corpses, wall and moving-away interruptions. Record accepted event/segment/J sequence, whole-body COM/pelvis travel, max segment displacement, total kinetic energy/joint error and floor support. Existing max_displacement>.005 proves5mm mathematical movement, not perceptible rendered corpse motion; name it accordingly and reserve visible-quality acceptance for native GPU view.
- Predicted torque currently uses world point minus body origin. Current source creates one centred capsule at local origin, so this is valid for that fixed COM assumption. If a custom/offset COM is allowed, use the native COM-relative lever for energy prediction while retaining API's world-axis offset-from-origin for apply_impulse. Either assert current centred COM or support it explicitly. Do not change shapes/masses to make the bound pass.
- The9-halving loop is bounded; after the last failed trial it halves once more but rejects using previous predicted values. This is conservative false rejection, not excess-force acceptance. Keep returned predicted values tied to the actual admitted impulse. Add explicit finite checks for native linear/angular velocity and computed delta-v/delta-w/energy to preserve fail-closed behavior if upstream physics is invalid.
- No explicit `body.sleeping=false` is required: Godot documents apply_impulse waking sleeping bodies. Read sleeping/response after a physics step; immediate sleeping_after_call may be a cached property. See [Godot RigidBody3D sleeping documentation](https://docs.godotengine.org/en/4.5/classes/class_rigidbody3d.html). No need to enable masks or force wake through a different path.
