**A) Мягкий осевой вход без расширения бокового допуска и без ослабления брони**

**Факты:** `weapon_solid_contact29` уже принимает позу только после swept/static/world/self/target проверок; активный bore требует identity generation/weapon/actor, точный skin entry patch, `axisdot>=.985`, реальную сужающуюся стальную эллиптическую зону +2 мм. Расширять её не нужно. `_constrain_walk_velocity` режет запрос по фактическому front tip и точному sweep до hit fraction минус 3 мм. `sword_puncture_resistance29` имеет `MAX_LAG=.035`, `SLOW_FRACTION=.20`, боковой guide 6 см/1.2 м/с и финальную solid-проверку. `armor_contact31` — это coverage skin-hit, не outer decorative plate collision; classifier головы сейчас `y<-.77 skin, иначе cloth/plate` + мелкие visor gaps, независимо от реального визуального light cap. Симптом на скриншоте (блок на открытом рте/подбородке) поэтому **может быть ложным покрытием брони**, а не чрезмерным сопротивлением ткани.

**Предлагаю минимально:**
1. **Сначала диагностика без геймплей-изменений.** На хите логировать: точку контакта, canonical part, `_armor_point31`, результат `armor_contact31`, признак реального cover/открытой зоны. Отдельно проверить тот же луч/свип по рту/подбородку и по crown/helmet. Это отделит ложный armor-classifier от осевого трения.
2. **Точечно исправить ложное покрытие light-cap головы.** Не делать «blanket head bypass». Для light-cap использовать реальную зону покрытия/маску/каноническую часть, а при отсутствии — узкую crown/helmet-оболочку. Рот/подбородок должны классифицироваться как открытая ткань; crown/helmet/visor-зоны остаются защищёнными. Не менять `weapon_solid_contact29`, `axisdot`, эллипс, GAP3 мм и боковой bore.
3. **Смягчать только подтверждённый осевой вход в открытую ткань.** В `sword_puncture_resistance29` добавить один skin-only коэффициент к осевому lag/сопротивлению (направление и величину подобрать тестами; не трогать armor-ветку). Для копья — тот же принцип только для реального forward request ≤3 см; не вводить idle-таймер, не менять удержание по bore axis, withdrawal `*.38`, lateral drag по фактическому swept-движению цели. Не ослаблять `MAX_LAG`/боковые ограничения глобально; лучше один ограниченный skin-множитель, чтобы не было «телепорта» и прохода через броню.
4. **Сплошная броня — отдельный acceptance.** Если быстрый удар всё ещё проходит через сплошную плиту из-за residual energy gates, это дефект брони, а не повод расширять skin-допуск. В этом scoped-изменении не ослаблять броню; при провале теста — отдельный минимальный фикс брони.

**Тесты A:** одинаковые скорость/угол/точка: сплошная плита не пробивается; точное открытое окно/рот/подбородок — входит мягче; crown/helmet/visor — защищены; быстрый удар по сплошной броне — блок. Start/continue/stop/reverse: остановка сохраняет lag, реверс освобождает по advance/withdrawal `.38`; mouse/up/side не извлекают; движение цели даёт lateral drag только по фактическому sweep. 30/60/120 fps — одинаковый результат в допуске. G/E сохраняют ту же рану; death/reset чистят. Нет idle drilling: стоящее копьё само не углубляется; только реальный forward ≤3 см. Не сломать existing strong cuts (`3.2 м/с`, alignment `.55`, реальные 40 мм) и exact ridge proof. Ложные срабатывания тестов: classifier может назвать skin там, где визуально броня, и наоборот; проверять края/visor/нормализованную box-зону по реальному покрытию, а не только по `y<-.77`.

**B) Минимальный визуальный helper для далёких стрел**

**Факты:** `_step_arrows` — только физика; гравитация/скорость 16–54 м/с и tip sweep не меняются; root orientation идёт по velocity, кроме rebound tail-first; root нельзя масштабировать из-за `ARROW_TIP_OFFSET31`, tip collision и embedded geometry. Pool 44, mesh/material переиспользуются. `_process` рано выходит при невыбранном/наземном луке. Helper можно масштабировать только поперёк/по минимуму пикселей, с depth-test, без фейкового tracer через стены.

**Предлагаю:** добавить **visual-only child** под root стрелы (тонкий quad/цилиндр/readability shell), не участвующий в collision и не меняющий root transform, tip offset, embed. Использовать уже существующий pooled mesh/material или один общий материал; без per-frame allocation. Масштабировать только helper поперёк, не root и не длину; цель — минимальная экранная толщина. Размер считать по проекции камеры: `scale = clamp(minPixels / projectedWidth, 1, maxScale)`, с гистерезисом по порогам включения/усиления и уменьшения, чтобы не мигало. Depth-test включён, occlusion сохраняется, без сквозь стены. Обновлять helper для активных flying arrows в ограниченном цикле ≤44; не в `_step_arrows`. Если ранний return в `_process` мешает обновлению после смены оружия, вынести обновление helper до него или в отдельный bounded visual pass. На stuck/recycle/reuse — helper hide/reset; после смены оружия летящие стрелы продолжают обновляться. Root/physics не трогать.

**Тесты B:** детерминированно сравнить траектории, tip sweep, damage, rebound tail-first и follow severed body до/после — без изменений. Проверить 16 и 54 м/с, near/far, светлый/тёмный фон, стену/листву, 30/60/120 fps, pool reuse, смену оружия. Нет per-frame создания material/mesh, нет ray fan. Ложные positives: projection у края/за камерой, прозрачные поверхности и depth-test, слишком большой min-pixel clamp у близких стрел, дребезг гистерезиса; проверять по реальной геометрии и depth buffer, а не по «красивости».
