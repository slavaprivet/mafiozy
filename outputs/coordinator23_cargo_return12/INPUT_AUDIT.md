The accepted window Take handler originally transferred/equipped the UID but kept the modal open. Modal opening sets `Input.mouse_mode=VISIBLE` while retaining `player._free_mouse_look=true`. That is coherent only while the modal owns input. A close/invalidation leaving that pair behind causes the next scene LMB to enter weapon input instead of the player's capture-only branch, which checks the logical flag rather than native pointer mode.

Actual route: weapons `_input` handles modal keys first, excluding GUI navigation/activation keys; cargo `_input` returns while modal. GUI receives mouse/button activation. Player `_unhandled_input` sees only unhandled events and sends them to weapons after its capture-only branch. The stock Take Button emits `pressed` on RELEASE, so that release alone cannot create a weapon press. Claiming the default Take release necessarily shoots would be inaccurate. Risks are stale held inputs, press-mode activation, modal removal during dispatch, and the mismatched capture state after other closure paths.
