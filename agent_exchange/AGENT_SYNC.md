# AGENT_SYNC — протокол обмена заданиями и результатами

Ветка обмена: `agent-exchange`. Здесь **не меняется игровой код** — только эти три файла.
Репозиторий: https://github.com/slavaprivet/mafiozy

## Кто что пишет

| файл | пишет | читает |
|---|---|---|
| `agent_exchange/AGENT_SYNC.md` (этот файл) | по согласованию обеих сторон | все |
| `agent_exchange/MESSI_TASKS.md` | **только Messi** | DeepSeek |
| `agent_exchange/DEEPSEEK_REPORTS.md` | **только DeepSeek** | Messi |

Никто не редактирует чужой файл. Нужно уточнить, возразить или оспорить ID — пишем в **свой** файл, ссылаясь на ID.

## Формат задания (Messi → DeepSeek)

```
### TASK <ID>
- цель:            <одна фраза, что должно измениться в поведении игры>
- разрешённые изменения: <файлы/подсистемы; можно ли менять игровой код>
- критерии проверки: <какие числа и на какой сцене доказывают результат>
- запрещено:       <например: не сокращать население, не ухудшать визуал, не трогать пины>
- ожидаемый артефакт: <патч/отчёт/цифры до-после>
```

ID: `MAF-<номер>` (как в Linear) или `EXT-<ГГГГММДД>-<n>`.
**Один ID выполняется один раз.** Неоднозначное задание — сначала уточняющий вопрос, потом работа.

## Формат отчёта (DeepSeek → Messi)

```
### REPORT <ID>
- принятие:        принято / отклонено (почему) / нужно уточнение
- статус:          сделано / в работе / заблокировано
- версия сборки:   путь пакета, sha затронутых скриптов, значения флагов по умолчанию
- изменения:       файл → что именно + флаг отката
- измерения:       до/после парным замером, число сэмплов, перцентили
- инварианты:      население, DSH_ECON conserved, парсер, пины
- блокеры:         ...
- чего не смог установить: ...
```

## Правила публикации

1. Перед записью — `git fetch` (свежая ветка), затем `git pull --rebase`; конфликтов быть не должно, потому что каждый пишет только свой файл.
2. Только **добавление** в свой файл. Историю не переписывать. **Force-push запрещён.**
3. В коммит попадают только файлы из `agent_exchange/`. Ветка `main` и игровой код этой веткой не трогаются.
4. Секреты, токены, ключи и посторонние файлы не публикуются.
5. После push — проверить, что коммит виден на сервере (`git ls-remote origin agent-exchange`), а не только локально.

## Как устроена проверка результата

Приёмка правок в этом проекте: **только парный замер** (правка выключена / включена) на одной сцене и при одном населении, с проверкой загрузки обеих рук. Замеры идут через скрипт-защиту (отказывается работать на занятой машине) и печатают перцентили, а не средние. Медианы на бимодальных распределениях врут — сравниваются средние и перцентили.
